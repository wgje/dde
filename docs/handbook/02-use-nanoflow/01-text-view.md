# 文本视图

文本视图是 NanoFlow 的主工作区。绝大多数日常任务管理都应该在这里完成：创建任务、拆分任务、编辑正文、调整层级、搜索、批量处理、删除和恢复。

## 文本视图适合做什么

优先在文本视图里做这些事：

- 快速新增任务；
- 修改任务标题；
- 给任务写执行说明；
- 把任务拆成子任务；
- 调整任务顺序和父子关系；
- 搜索某个项目或任务；
- 批量删除低价值任务；
- 从回收或归档入口恢复内容。

如果你只是要推进工作，不需要先打开流程图。流程图适合“看关系”，文本视图适合“真正编辑和推进”。

## 创建任务的建议方式

一个清晰任务通常包含三层信息：

1. **标题**：一句话说明要做什么，例如“整理下载目录里的合同文件”。
2. **正文**：写执行步骤、判断标准、链接、注意事项。
3. **位置**：放在正确项目、正确父任务、正确阶段下。

不建议这样写标题：

- `处理一下`
- `资料`
- `待办`
- `看情况`

建议改成：

- `整理下载目录中的合同 PDF`
- `确认 Supabase Storage bucket 权限`
- `把本周复盘草稿补成可发布版本`

标题越清楚，搜索和 Focus 推荐越有用。

## 任务层级怎么组织

层级不是越深越好。推荐结构：

```text
项目目标
  - 阶段或工作包
    - 可以执行的具体任务
      - 必要时再拆的子步骤
```

使用建议：

- 顶层任务写结果，不写零散动作。
- 子任务写动作，尽量能在一个工作时段推进。
- 如果层级超过几层还看不清，说明应该拆项目或重命名中间节点。
- 不要把长篇资料塞成很多层任务；资料适合放在思源或外部文档里。

## 正文、Markdown 和链接

任务正文适合写：

- 清单；
- 执行步骤；
- 外部链接；
- 本地文件路径；
- 关联任务；
- 简短背景；
- 验收标准。

示例：

```markdown
目标：把合同文件按年份归档。

- [ ] 找到下载目录里的合同 PDF
- [ ] 按年份放入对应文件夹
- [ ] 命名成“年份-客户-事项”

参考目录：D:\Documents\Contracts
```

链接处理细节：

| 写法 | 用途 | 注意 |
| --- | --- | --- |
| `https://example.com` | 外部网页 | 会按外链处理 |
| `./docs/guide.md` | 相对文档路径 | 写成真实链接前，先确认目标文件存在 |
| `task:<taskId>` | 关联 NanoFlow 任务 | 适合稳定任务内链 |
| `C:\Users\me\Docs\Plan.md` | Windows 本地路径 | 路径有空格时用 Markdown 链接 |
| `file:` 链接 | 本地文件入口 | 应走受控处理，不直接暴露原始 file URL |

高风险本地路径、网络共享路径和可执行文件不应该被随意直接打开。

## 搜索和批量操作

搜索适合用来“回到上下文”：

1. 输入关键词。
2. 打开匹配任务。
3. 修改标题、正文或状态。
4. 清空搜索，再进行拖拽或批量整理。

批量操作前请先判断风险：

- 只是批量移动低价值测试任务：可以直接做。
- 要删除真实任务：先导出 JSON。
- 要整理包含附件的任务：同时确认附件 ZIP 备份。
- 多设备开启同步时：等当前同步状态稳定后再做大批量操作。

## 移动端使用细节

手机端默认应该使用文本视图，因为它比流程图轻：

- 卡片布局更适合窄屏；
- 长按或触控操作更适合移动端；
- 侧栏通常通过手势打开；
- 流程图按需加载，避免启动慢和内存压力；
- 大量编辑时仍建议回到桌面端操作。

如果你发现手机上操作很慢，先确认是不是长期停留在流程图视图。
