# 使用 NanoFlow

这一组文档解释 NanoFlow 的日常使用方式。你不需要每天打开所有功能；最稳定的使用节奏是：文本视图处理大多数任务，Black Box 负责快速收集，Parking Dock 暂存“之后再做”，Focus 收窄当前工作，流程图只在关系复杂时打开。

## 推荐日常节奏

1. **打开应用后先看文本视图**：它是任务树和执行状态的主界面。
2. **想到新内容先丢进 Black Box**：不要为了记录一个想法打断当前任务。
3. **整理任务时再把 Black Box 转成任务**：不是每条记录都值得变成任务。
4. **暂时不做但不能忘的任务放入 Parking Dock**：不要让它继续挤在当前任务列表里。
5. **准备工作时进入 Focus**：只挑当前时段真正要推进的少量任务。
6. **关系复杂时打开流程图**：用它看结构、连线、布局和导出，不要在手机端常驻。

## 每个功能什么时候用

| 功能 | 最适合的场景 | 不适合的场景 |
| --- | --- | --- |
| [文本视图](01-text-view.md) | 快速编辑任务、整理层级、搜索、批量处理 | 大量关系线和空间结构判断 |
| [流程图视图](02-flow-view.md) | 看任务关系、依赖、结构布局、导出图 | 手机端日常快速编辑 |
| [Parking Dock 停泊坞](03-parking-dock.md) | “不是现在做，但之后要回来”的任务 | 永久归档、删除无用任务 |
| [Focus 专注模式](04-focus-mode.md) | 当前时段只处理少量事项 | 存放完整项目计划 |
| [Black Box 黑匣子](05-black-box.md) | 快速记录想法、语音、临时输入 | 长期保存任务状态 |
| [思源知识锚点](06-siyuan-knowledge-anchors.md) | 把任务连接到思源块或资料来源 | 把 NanoFlow 变成第二个知识库 |
| [Android 小组件](07-android-widget.md) | 在手机桌面看摘要和提醒 | 完整编辑任务 |

## 不要混淆的几个概念

| 概念 | 正确理解 |
| --- | --- |
| 任务 | 需要推进的执行单元 |
| Black Box 记录 | 临时收集的信息，后续要处理或丢弃 |
| 停泊任务 | 暂时不推进，但需要保留在未来注意力范围内 |
| 归档任务 | 长期不活跃，但保留记录 |
| 删除任务 | 从当前工作中移除，依赖恢复窗口和备份兜底 |
| Focus 队列 | 当前时段要看的少量任务，不是完整项目列表 |

## 一天中的典型流程

早上：

1. 打开文本视图，看当前项目和停泊提醒。
2. 打开 Focus，处理 Gate 中的 Black Box 项目。
3. 只挑 1 到 3 个任务进入当前专注范围。

工作中：

1. 新想法先记到 Black Box。
2. 被阻塞的任务放进 Parking Dock，并写清楚等待原因。
3. 关系变复杂时打开流程图查看结构。

收尾时：

1. 回到文本视图，确认任务状态。
2. 把未完成但暂时不推进的任务停泊或留下明确下一步。
3. 重要整理完成后导出 JSON 或确认自动备份。
