# 流程图视图

流程图视图基于 GoJS，用来查看任务之间的关系、结构和空间布局。它不是文本视图的替代品，而是当“列表看不清关系”时打开的辅助视图。

## 什么时候打开流程图

适合打开流程图的情况：

- 任务之间有依赖关系；
- 一个任务连接多个后续动作；
- 你想看项目全局结构；
- 你需要把结构导出给别人或给 AI 审阅；
- 文本列表里已经看不出哪几件事互相影响。

不建议打开流程图的情况：

- 只是快速新增一条任务；
- 只是修改任务标题；
- 只是在手机上临时看一眼；
- 当前项目很小，列表已经足够清楚。

## 你能在流程图里做什么

流程图通常用于：

- 缩放和平移画布；
- 查看任务节点；
- 选中节点；
- 创建或查看连线；
- 调整结构布局；
- 框选多个节点；
- 导出 PNG 或 SVG；
- 导出项目逻辑 Markdown；
- 查看小地图或概览区域。

具体按钮名称可能随界面版本变化，但使用原则不变：图用于看关系，文本视图用于主要编辑。

## 用 Constellation 小地图定位关键状态

右下角的 Constellation 小地图把整张流程图压缩成一幅低对比的“星图”。静止时它会刻意保持安静，只显示必要的节点、连线和当前视口；只有在指针、滚轮、键盘或焦点产生有效交互并持续约 240 毫秒后，注意力镜头与图例才会一起浮现。镜头坐标随后按帧合并更新，附近轮廓更清楚，远处仍然偏淡，因此小地图可以帮助定位，但不会持续抢占画布的第一视觉。

小地图中的特殊状态优先使用几何轮廓表达，颜色只是辅助：

| 标记 | 几何形状 | 表示什么 |
| --- | --- | --- |
| 僚机 | 四芒星 | 任务带有需要留意的僚机信号 |
| 思源 | 空心菱形 | 任务关联了思源知识锚点 |
| 入坞 | 开口方框 | 任务已进入停泊坞相关流程 |
| 停泊 | 中断描边 | 任务处于停泊状态；同时使用琥珀色辅助识别 |
| 专注 | 外环 | 任务是当前需要关注的停泊或专注目标 |
| 搜索 | 十字准星 | 任务命中当前搜索 |

使用主鼠标键或主触点拖动小地图可平移画布，右键、中键和第二触点不会夺取拖动；滚轮可缩放。获得键盘焦点后，也可以使用方向键平移、使用 `+` 和 `-` 缩放。桌面端图例在地图内以轻量浮层显示；手机端 100×80 的小地图只常驻一个 24px 图例入口，点击后完整图例会锚定在小地图上方。

点击图例项目只会临时隐藏或显示对应类别，不会修改任务、连线、同步数据或项目存储。关闭小地图、切换 SVG/GoJS 概览模式或离开当前组件后，临时筛选会自动重置。浅色主题使用瓷白星图，深色主题使用深空星图；两种主题都保留相同的几何含义，不能只凭颜色判断状态。

正常情况下会显示 SVG Constellation；内部兼容开关启用时，可以回退到旧的 GoJS Overview。回退只影响概览的绘制方式，主键拖动、滚轮、方向键和缩放操作仍然保留，也不会改变流程图数据。若切换后概览短暂重建，等待它重新出现再继续操作即可。

## 和文本视图如何配合

推荐流程：

1. 先在文本视图里把任务标题和层级整理清楚。
2. 打开流程图查看关系是否符合直觉。
3. 如果发现结构混乱，回到文本视图重命名或拆分任务。
4. 只有当任务之间确实存在关系时，再添加连线。
5. 导出图或 Markdown 作为审阅材料。

不要用大量连线掩盖糟糕的任务命名。标题和层级清楚，流程图才有意义。

## 先分清父子关系和跨树连接

流程图里最容易造成后续混乱的不是布局，而是把不同含义的线混在一起。先判断你要表达的是“任务属于哪个父任务”，还是“两个独立任务之间存在依赖或参考”。

| 关系 | 应该表达什么 | 适合例子 | 不适合例子 |
| --- | --- | --- | --- |
| 父子关系 | 拆解后的层级与归属 | “发布版本”下面的“编写说明”“验证回滚” | 两个项目之间只是互相参考 |
| 跨树连接 | 不改变任务层级的依赖、阻塞、参考或关联 | “确认合同”依赖“收到报价单” | 用来代替真正的任务拆分 |

父子关系表示结构，跨树连接表示关系。一个任务可以有合理的跨树连接，但不应同时靠多条线来猜它到底属于哪个项目。先在文本视图把父子层级整理好，再用跨树连接标出真正会影响执行顺序的关系。

在移动端长按一条线会显示对应的操作菜单：跨树连接可以编辑或删除；父子关系可以查看或解除。解除父子关系会把子任务移到“待分配”，不是删除该任务。删除跨树连接只移除这条关系，不会删除两端的任务。执行前先读清菜单标题，不要把“解除”理解成“删除”。

## 编辑连接和规划字段

跨树连接有自己的标题和描述，用来说明“为什么存在这条线”。编辑器默认先以预览方式打开；进入编辑后，标题和描述会在停止输入后短暂延迟保存，点击编辑器外部也会先保存再关闭。写完重要说明后，先等待内容稳定或主动离开编辑区，再选择另一条线或切换视图。

连接描述适合写依赖条件、确认来源、下一次复查点和相关链接，不适合替代任务正文。若一段信息只对其中一个任务有意义，写在该任务正文；若它解释两者关系，写在连接描述。对复杂依赖先用一两句人能读懂的语言，再添加细节，避免把连接名写成无意义的“关联”“链接 1”。

流程图中的连线、任务详情和规划字段都应当按“修改一次、确认一次”的节奏操作：

1. 创建或调整连线前，先确认两个节点分别代表什么任务，避免把视觉相邻误当成业务相关。
2. 保存连线后，观察节点间是否出现预期关系；如果没有，先重新打开该连接或返回文本视图核对，不要连续重复点击保存。
3. 修改预计时长、等待时间、认知负荷等规划信息后，回到任务详情确认数值仍然存在。等待时长不应超过当前预计投入；出现校正提示时，先拆分任务而不是继续堆大数值。
4. 手机端进行缩放、拖动或调整大小时，先完成当前手势再开始下一次操作；连续多指或快速切换工具会让你难以判断到底是哪一次保存生效。
5. 关系复杂时，先导出项目逻辑 Markdown 审阅，再批量修改连线；这样更容易发现错误关系。

流程图负责呈现结构，任务的标题、正文和层级仍以文本视图中的状态为准。

## 批量选择、解除和删除

框选和批量工具适合对同一层级的一组任务执行明确的整理动作，不适合在看不清范围时“试一下”。特别是批量删除：确认窗口会分别显示你显式选中的任务、会级联进入回收站的子任务，以及总数。确认删除后，任务会移动到回收站而不是立刻永久删除，但它仍会影响当前项目、Flow 结构和后续同步。

安全顺序：

1. 先缩放或打开小地图，确认没有把相邻但不相关的节点框进来。
2. 查看确认窗口中的“级联子任务”数量；数量意外增大时取消，回到文本视图检查层级。
3. 删除前导出当前 JSON；有关键附件时同时导出 ZIP。
4. 删除后只恢复一条代表性任务，确认层级和连接符合预期，再做更多恢复或清理。

批量选择也可能用于调整关系或任务位置。拖动改变的是图上的操作结果，但不要把视觉位置当成任务优先级或父子关系本身；需要改变层级、状态或正文时，使用明确的任务编辑入口。误解除父子关系时，先在“待分配”里找到子任务并重新分配，不要重新创建一个同名任务来掩盖原记录。

## 手机端为什么按需加载

流程图比文本视图重，尤其在手机上更明显。NanoFlow 的移动端规则是：

- 手机默认文本视图；
- 需要时才加载流程图；
- 离开流程图时应释放图实例；
- 不应该用 `visibility:hidden` 把图藏起来但继续占内存；
- 再次打开时从当前状态重建。

这能减少启动时间、内存压力和移动端卡顿。

手机端进入 Flow 时会先收起当前节点详情，避免旧选择遮挡画布。优先用节点详情和右侧面板完成精确编辑；对连接线使用长按菜单，而不是在缩放过程中误触。手势或抽屉把你带回文本视图、打开面板或清空选择时，先停下来确认当前项目和节点，再继续操作。

复杂的批量操作、长连接描述和大范围布局在桌面端更容易核对。手机上出现“我不知道刚才改了哪条线”的情况时，切回文本视图或在桌面端打开同一项目验证，不要靠连续撤销或反复缩放猜测状态。

## 导出图和导出 Markdown

| 导出类型 | 适合用途 |
| --- | --- |
| PNG | 快速发给别人看结构截图 |
| SVG | 需要放大查看或放进文档 |
| 项目逻辑 Markdown | 需要让人或 AI 阅读项目脉络、任务关系和结构 |

如果你要讨论“项目逻辑是否合理”，Markdown 通常比图片更好，因为它可以被搜索、复制和审阅。

## 常见问题

| 问题 | 先检查什么 |
| --- | --- |
| 手机上打开慢 | 是否真的需要流程图，能否先用文本视图 |
| 图看起来过于复杂 | 是否任务命名太含糊，是否层级拆得太碎 |
| 导出图缺少上下文 | 改用项目逻辑 Markdown |
| 节点关系不对 | 回文本视图检查任务和连接是否符合真实工作 |
| 解除父子关系后找不到任务 | 到“待分配”查找，不要立刻新建同名任务 |
| 批量删除数量比预期多 | 取消确认，检查级联子任务和当前项目，再导出后重试 |
| 编辑连接后马上看不到文字 | 等编辑器保存并重新打开该连接；仍不对时停止连续编辑，检查同步状态 |
