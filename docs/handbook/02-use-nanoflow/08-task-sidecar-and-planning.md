# 任务僚机与计划信息

任务僚机是任务上的一层“注意力摘要”。它把当前值得留意的计划字段、未完成注意事项、风险、资料、状态和标签压缩成短徽标，让你在不逐个打开任务的情况下先判断应该看哪里。

它不会创建新任务、不会改变父子层级、不会新增流程图关系，也不会替你决定任务是否应该进入 Focus。它的作用是帮助你扫读和判断，而不是替代任务正文、待办清单或真实的任务关系。

## 任务僚机显示什么

任务僚机会从任务已有信息中整理出摘要。不同任务显示的徽标不一定相同；只有存在且值得提示的信息才会出现。

| 信息 | 用来回答的问题 | 适合填写什么 |
| --- | --- | --- |
| 未完成注意事项 | 做这件事之前或过程中要特别留意什么？ | `先确认接口字段是否冻结`、`等报价单后再提交` |
| 风险提示 | 这件事是否有优先级、截止或阻塞风险？ | 保持任务的优先级、日期和状态准确，不要把风险只写在聊天记录里 |
| 预计时长 | 真正动手时大约需要多少有效工作时间？ | `25`、`60` 这类分钟数 |
| 等待时间 | 是否要等待外部输入、审核、回复或时间窗口？ | `20`、`1440` 这类分钟数；等待原因写进注意事项或正文 |
| 认知负荷 | 这件事是否需要高强度、连续的注意力？ | 高负荷用于深度思考、复杂排查；低负荷用于整理、确认、重复操作 |
| 资料和状态 | 是否有知识锚点、附件或当前停泊、专注等状态？ | 让资料和任务状态保持真实，不要用徽标代替实际操作 |
| 标签 | 任务属于哪个主题或工作流？ | 用少量稳定标签，避免把完整说明塞进标签 |

流程图上常见的是很短的提示，例如“风险”“等待”“高负荷”或“注意”。短标签用于快速扫读；完整的注意内容应在任务详情或文本编辑器中查看。

任务僚机只把仍未完成且文字不为空的注意事项当作当前提示。清空一条注意，或让它不再处于当前未完成状态后，它不应该继续作为需要立即关注的摘要出现。

## 计划字段、注意事项、正文和关系的区别

这四类信息解决不同问题。把它们分开写，后续搜索、停泊、专注和流程图阅读都会清楚得多。

| 信息类型 | 应该写什么 | 不应该拿来代替什么 |
| --- | --- | --- |
| 预计时长 | 实际投入的分钟数，例如 `45` | 截止日期、等待时长或完整执行步骤 |
| 等待时间 | 不能主动推进的等待分钟数，例如 `120` | 等待原因和催办对象；这些放在注意事项或正文 |
| 认知负荷 | 高或低，反映需要的专注强度 | 优先级；高负荷不等于一定更重要 |
| 注意事项 | 前提、风险、提醒、外部依赖，例如“先备份配置” | 可勾选的执行清单或长篇方案 |
| 任务正文 | 背景、步骤、链接、验收标准、决策记录 | 一眼扫读用的短提示 |
| 流程图关系 | 父子结构和真正的跨任务关联 | “别忘了做什么”的个人提醒 |

一个实用的写法是：标题写动作，正文写步骤，计划字段写时间和负荷，注意事项写前提或风险。例如：

```text
标题：确认客户合同最终版本
预计时长：30 分钟
等待时间：1440 分钟
认知负荷：低
注意事项：等法务确认条款后再发送
正文：
1. 比对客户修订稿和法务意见。
2. 确认附件命名与版本号。
3. 邮件发送前保存 PDF 副本。
```

不要把“等法务确认”写成子任务后又设置为高负荷。它通常是等待状态，不需要占用深度工作的注意力；真正需要专注的是确认、比对和发送这些可执行步骤。

## 在文本视图编辑计划和注意事项

文本视图适合完整编辑。打开一个任务的编辑状态后，可以调整预计时长、等待时间、认知负荷和注意事项。

### 填写计划字段

1. 先判断任务是否已经足够清楚。标题仍是“处理一下”时，不要急着估时。
2. 填写预计时长，写本次真正需要投入的有效分钟数，不包含睡觉、等回复或排队的时间。
3. 有外部等待时填写等待时间；同时在正文或注意事项中写清楚等待谁、等什么、何时复查。
4. 选择认知负荷。需要连续思考、排查、写作或高风险判断的任务标为高负荷；能在碎片时间完成的整理、确认和重复操作标为低负荷。
5. 修改后等待保存状态稳定，再切换任务或关闭编辑器。

要移除一个可选计划字段时，清空对应值并完成一次保存。不要只把光标移走就假定修改已经提交；以界面恢复稳定和任务摘要实际变化为准。

### 填写注意事项

注意事项适合短句，每条只表达一个前提、风险或提醒：

- `发邮件前先确认收件人权限`
- `接口还在灰度，先用测试账号验证`
- `不要覆盖上周已确认的预算表`
- `等待设计给出最终尺寸`

推荐操作顺序：

1. 在任务编辑器中选择添加注意事项。
2. 每行或每个输入项只写一条提醒。
3. 需要多条时继续添加，不要把几个互不相关的条件挤成一长句。
4. 不再适用时删除该条，或清空它后离开输入框。
5. 注意事项较多时使用“展开”查看全部，再逐条整理；不要把它变成第二个任务清单。

如果某项提醒已经变成了可独立推进的工作，例如“向法务催一次合同”，应新建任务或子任务。注意事项应该保留为做主任务时需要记住的上下文。

## 在流程图中阅读任务僚机

流程图适合用任务僚机快速扫读复杂项目：先找风险、等待和高负荷信号，再决定是否打开任务详情。

### 先看短徽标，再打开详情

1. 在 Flow 视图中观察任务块上的任务僚机摘要。
2. 看到风险、等待、高负荷或注意事项时，先判断它是否影响当前安排。
3. 在桌面端，把指针停在徽标上查看完整提示；短标签本身不适合承载长文本。
4. 需要修改时打开该任务的详情，在详情编辑区调整同一组计划字段和注意事项。
5. 在手机或没有悬停能力的设备上，直接打开任务详情查看完整内容。

任务僚机的徽标只是摘要，不能当作新的流程图节点或连线。想表达真实依赖、引用或父子关系时，仍应使用 [流程图视图](02-flow-view.md) 中的任务结构和关系能力。

### 徽标看起来不对时先检查什么

按下面顺序排查，通常不需要立刻刷新页面：

1. 打开任务详情，确认计划字段和注意事项是否已经完成保存。
2. 检查注意事项是否为空、已不再需要，或只是被折叠在更多内容中。
3. 检查任务是否仍处于停泊、专注或其他会影响状态摘要的状态。
4. 有多台设备时，先让修改所在设备的保存和同步稳定，再在另一台设备确认。
5. 仍不一致时，记录任务标题、项目和你刚刚修改的字段，再按 [同步与冲突处理](../03-data-sync-safety/02-sync-and-conflicts.md) 的顺序检查。

## 保存中或保存失败时怎么处理

计划字段和注意事项都有独立的保存过程。编辑时可以把界面状态理解为三种情况：

| 状态 | 应该怎么做 |
| --- | --- |
| 稳定或空闲 | 可以继续编辑、切换到下一个任务，随后再看同步状态 |
| 保存中 | 不要马上重复点击同一项；先等当前保存结束，再确认摘要和输入值 |
| 保存失败 | 保留当前输入，不要立刻刷新或重新输入；检查网络和同步状态后重试 |

保存失败时建议这样处理：

1. 先确认当前编辑框里的文字和数值还在。
2. 如果准备刷新、切换账号或清理浏览器数据，先把尚未确认保存的长文本复制到安全位置。
3. 检查应用是否处于离线、登录过期或同步异常状态。
4. 恢复连接后重试保存，并确认任务摘要是否更新。
5. 同一字段不要在多台设备同时改。先在一台设备完成保存和同步，再在另一台设备继续编辑。

本地界面已经变化并不等于云端已经完成同步。重要任务在跨设备继续编辑前，应等同步状态稳定；大批量整理前仍应先做备份。

## 跨项目搜索如何定位普通任务和停泊任务

搜索结果可能来自当前项目，也可能来自另一个项目。NanoFlow 会先判断任务所属项目；项目不同的时候，先切换到目标项目，再执行对应的定位动作。

### 普通任务

选择普通任务后，应用会把焦点放到该任务的 Flow 节点。你应先确认项目已经切换到正确项目，再检查该节点的标题、层级和任务僚机摘要。

### 停泊任务

选择已经停泊的任务时，应用不会把它当作普通节点直接聚焦，而是：

1. 切换到任务所属项目；
2. 等目标项目成为当前项目；
3. 展开 Parking Dock；
4. 打开该停泊任务的预览。

这只是在 Parking Dock 中查看任务，不会自动恢复、完成或删除它。确认可以继续推进后，再按 [Parking Dock 停泊坞](03-parking-dock.md) 的流程恢复任务或送入 Focus。

连续选择多个搜索结果时，以最后一次选择为准。若项目刚切换完成但没有看到预览，先确认当前项目和 Dock 是否已打开，再重新选择一次该搜索结果；不要在切换过程中连续拖拽、恢复或修改同一任务。

## 推荐使用方式

- **排计划时**：先写清标题和正文，再估时、标等待、选认知负荷。不要为模糊任务制造精确数字。
- **开始工作前**：扫一遍 Flow 徽标，优先找阻塞、等待和高负荷任务，避免只按标题排序。
- **被打断时**：在注意事项里写下一次回来时必须知道的前提，不要依赖记忆。
- **准备停泊时**：把等待原因和回来后的第一步写清楚，再设置停泊信息；任务僚机只负责提示，不会自动替你恢复。
- **多设备使用时**：同一任务的计划字段和注意事项一次只在一台设备集中编辑，等同步稳定后再换设备。
- **定期整理时**：删除过期提醒、拆出真正的行动项，并把长篇说明移回任务正文或知识锚点。

## 常见问题

### 为什么我写了注意事项，却没有看到对应摘要？

先确认该条文字不为空、仍属于当前未完成的注意事项，并且保存已完成。注意事项较多时，部分内容可能需要展开后才能看到；在 Flow 视图中，完整文字通常应通过桌面端悬停或任务详情查看。

### 高负荷是不是代表最高优先级？

不是。高负荷描述的是需要的注意力强度，优先级描述的是重要性和紧急性。一个重要但流程固定的确认任务可以是低负荷；一个高负荷的研究任务也未必今天必须做。

### 等待时间应该填多久？

填你预计不能主动推进的时间，而不是你希望对方多久回复。等待原因、联系人和催办条件写到注意事项或正文，这样未来重新看到任务时才知道下一步。

### 任务僚机能代替待办清单或流程图连线吗？

不能。待办清单记录要做的步骤，流程图关系记录任务之间的真实结构，任务僚机只记录当前需要注意的摘要。三者混用会让任务难以搜索、估时和恢复。

### 系统会自动生成注意事项吗？

不会。当前摘要来自任务已有字段和你手动填写的注意事项。它不会调用 AI 自动生成提醒，也不应把未经你确认的内容写入任务。
