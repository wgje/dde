# 思源知识锚点

思源知识锚点用来把一个 NanoFlow 任务指向一个思源块。NanoFlow 当前保存的是锚点指针和少量展示信息，不是整篇思源正文，也不是文件附件。

这意味着它适合做“这项任务的资料来源在哪里”，不适合做“把资料全文搬进任务里”。

## 先分清锚点、任务正文和附件

| 入口 | 适合放什么 | 不适合放什么 | 关键边界 |
| --- | --- | --- | --- |
| 任务正文 | 执行步骤、清单、验收标准、外链、简短背景 | 长篇资料全文、二进制内容 | 正文是任务本身的一部分，按任务编辑和同步处理。见 [文本视图](01-text-view.md)。 |
| 思源知识锚点 | 指向思源块的来源指针、只读预览、回跳入口 | 文件上传、整篇知识镜像、在 NanoFlow 内改写思源正文 | 锚点保存的是块指针和轻量元数据；预览缓存默认只留在当前设备。 |
| 附件 | PDF、截图、导出文件、会议材料等真实文件 | 代替任务正文的说明文字，或代替思源知识库的长文 | 附件有独立的上传、扫描、下载和删除流程。见 [附件与文件安全](10-attachments-and-file-safety.md)。 |

如果你只是想写“下一步做什么”，用任务正文。

如果你要保留一个真实文件，走附件入口。

如果资料本体已经在思源里，且你希望任务能回到那个原块，用知识锚点。

## 什么时候该用知识锚点

适合用锚点的情况：

- 任务依赖一段已经存在于思源的会议纪要、需求原文、研究摘录或决策记录；
- 你希望在 NanoFlow 里看到一小段只读预览，但资料主权仍然留在思源；
- 你需要从任务快速跳回思源原块，而不是复制整段内容。

不适合用锚点的情况：

- 你只是想记几条执行说明；
- 你要上传文件、截图、录屏或导出物；
- 你需要在 NanoFlow 里直接编辑思源正文。

当前实现是“读预览 + 打开原块 + 替换关联 + 解除关联”，不是“在 NanoFlow 里改写思源”。

## 如何添加锚点

### 先确认你手里拿的是有效输入

当前绑定入口只接受两种输入：

1. `siyuan://blocks/{blockId}`
2. 直接粘贴思源块 ID

粘贴其他内容时，界面会提示：

```text
思源链接无效
请粘贴 siyuan://blocks/{id} 或思源块 ID
```

### 添加步骤

1. 打开一个可编辑的任务上下文。
2. 在知识锚点输入框里粘贴思源块链接或块 ID。
3. 提交后等待当前任务稳定。
4. 看到锚点 chip 后，再决定是否去配置实时预览。

几个当前行为需要提前知道：

- **绑定本身不依赖实时预览通道**。你可以先建锚点，之后再去设置思源连接。
- **同一任务重复绑定同一个思源块不会再造一个重复锚点**。
- **当前日常界面没有单独的“编辑标题/角色”表单**。用户侧能直接操作的是绑定、替换、打开、预览和解除关联。

## 如何查看、打开、替换和解除关联

### 桌面端

桌面端锚点以 `思源 {显示名}` 的 chip 形式出现。

默认交互是：

1. 鼠标悬停或键盘聚焦到 chip。
2. 约 `300ms` 后打开预览浮层。
3. 从 chip 移到浮层时，系统会给一个短暂关闭宽限，避免你刚移动过去就闪退。
4. 按 `Esc` 可以关闭浮层并把焦点还给原来的 chip。

浮层里当前有两个动作：

- `打开思源`
- `刷新`

桌面端直接点击 chip 时，默认是**打开思源原块**，不是打开底部预览面板。

### 移动端

移动端没有 hover 预览，改成点击和长按：

- **点一下**：打开底部预览 sheet。
- **长按或上下文菜单**：打开动作菜单。

底部 sheet 的常见可见状态有：

- `正在读取思源块…`
- 摘要正文或纯文本预览
- 子块列表
- `更多内容请打开思源`
- 错误提示框

当前可见按钮有：

- `打开思源`
- `刷新缓存`
- `修改关联`（仅可管理上下文）
- `解除关联`（仅可管理上下文）

长按菜单在完整预览模式下会给出：

- `预览`
- `打开思源`
- `刷新缓存`
- `修改关联`
- `解除关联`

### Parking Dock 这类轻量上下文

Parking Dock 当前使用的是 `deep-link-only` 紧凑模式。这里的锚点主要是“快速回到思源原块”，不会像普通任务卡那样弹出完整 hover 预览或移动端 sheet。

### 替换关联

当前“编辑”锚点的含义是**把当前锚点换成另一个思源块**，不是编辑思源正文。

替换时的行为是：

1. 系统把当前锚点的 `uri` 或 `targetId` 放回输入框；
2. 你粘贴新的块链接或块 ID；
3. 提交后，用新的块替换旧的关联；
4. 旧关联的本机预览缓存会一起清掉。

如果你把它替换成“同一任务里已经存在的另一个锚点”，系统不会保留两个重复项，而是切换到已有关联并删除旧项。

### 解除关联

`解除关联` 只会移除 NanoFlow 和这个思源块之间的关系，不会删除思源原块。

当前实现还会同时清掉这个锚点对应的本机预览缓存，避免之后继续看到旧块内容。

### 为什么有时只看到一个锚点

当前数据模型支持一个任务挂多个锚点，但界面不一定总把它们全展示出来：

- **可编辑或可管理上下文**：会展示当前任务的所有活跃锚点；
- **普通只读上下文**：默认只展示第一个锚点。

看到“只有一个”不一定表示其他锚点丢了，先回到可编辑任务上下文再核对。

## 预览模式和设置边界

### 当前三种运行模式

设置页里目前有三种模式：

| 模式 | 设置页名称 | 适合谁 | 你该期待什么 |
| --- | --- | --- | --- |
| `extension-relay` | 浏览器扩展 Relay（推荐） | 普通桌面使用者 | 推荐主路径。可以做实时预览，页面不留存 Token。 |
| `direct` | 本地开发直连 | 本地开发或受控环境 | 不是普通日常路径。要求本机直连思源，并且只信任 `127.0.0.1` 或 `localhost`。 |
| `cache-only` | 仅缓存与深链 | 只想保留本机缓存和回跳的人 | 不做实时抓取；有缓存时看缓存，没有缓存时通过深链回到原块。 |

### 先分清“日常使用”和“环境设置”

日常任务操作是：

- 绑定锚点；
- 看预览；
- 打开思源；
- 替换或解除关联。

下面这些更像当前设备的环境设置，不应当被当成每次做任务都要重复的普通动作：

- 安装或更新 NanoFlow 浏览器扩展；
- 处理“扩展版本过旧”；
- 到扩展 `Options` 页配置旧版扩展；
- 在本地开发直连模式下处理本机 token 和 localhost 限制。

如果设置页明确告诉你“请安装/更新扩展”或“请在扩展 Options 中配置”，这已经超出单个任务的锚点操作范围了。

### Relay 模式下你会看到什么

Relay 模式是当前推荐路径。设置页可能出现这些状态：

| 可见状态 | 表示什么 | 你该做什么 |
| --- | --- | --- |
| `正在读取扩展状态…` | 页面正在探测扩展状态 | 等待，不要连续重复点 |
| `扩展未安装或版本过旧，请安装/更新扩展后刷新页面` | 当前页面没有可用扩展通道 | 先处理设备/浏览器环境 |
| `当前扩展版本不支持页面配置读写；请在扩展 Options 中配置，或更新扩展后刷新页面` | 扩展预览通道可能还在，但页面端配置通道太旧 | 把它视为环境设置问题，不是任务问题 |
| `扩展已就绪，但尚未配置思源 Token，请在下方填写后点击"保存到扩展"` | 扩展在，授权还没写进去 | 在当前设备上完成一次授权 |
| `扩展已配置：{baseUrl}（Token 已写入扩展，页面不留存）` | 当前设备扩展侧已有可用授权 | 可以直接测试连接或去用锚点 |

Relay 模式下还有四个关键按钮：

- `保存到扩展`
- `测试连接`
- `清除本机缓存`
- `忘记本机授权`

其中最重要的边界是：

- 页面里输入的 token 在 Relay 模式下只会短暂留在内存里；
- 点击 `保存到扩展` 后，token 被单向写入扩展存储；
- 页面会立即清掉内存里的 token；
- 页面读取扩展状态时只拿到 `baseUrl` 和 `hasToken`，拿不到 token 明文。

### Direct 模式不是公网普通用户路径

设置页把 `direct` 标成了“本地开发直连”，这不是文案装饰，当前代码也确实这样限制：

- 只允许 `http://127.0.0.1:6806` 或 `http://localhost:6806`
- 页面本身还必须是本机页面或 `file:` 页面
- token 必填

如果你把 base URL 改成不被信任的地址，应用会直接把它重置回默认地址，并清掉本地 token，状态文案会明确告诉你只支持本机思源地址。

### Cache-only 模式意味着什么

`cache-only` 不是“假装在线”，而是明确只依赖：

- 当前设备已有的本机预览缓存
- 打开思源原块的深链

设置页测试连接时，它会明确显示：

```text
当前为仅缓存与深链模式
```

在这个模式下：

- 如果当前设备以前看过这个块并留下了缓存，可以继续看缓存；
- 如果当前设备没有缓存，不会帮你实时拉思源正文；
- 你仍然可以保留锚点并打开原块。

## 缓存、离线和多设备

### 本机缓存怎么工作

当前预览缓存按 `用户 + linkId + blockId` 隔离保存。

几个直接影响使用体验的点：

1. 有本机缓存时，界面会优先直接显示缓存。
2. 缓存超过 `24 小时` 后，系统会在后台尝试刷新，而不是先把你卡住。
3. 单设备预览缓存有数量上限，当前配置是 `200` 条。
4. `清除本机缓存` 只删除当前账号在当前设备上的思源预览缓存，不会删除锚点指针。

### 离线或弱网时会怎样

锚点增删改走的是“本地先写，再后台同步”的路径。

这意味着：

- 你刚绑定、替换或解除关联时，当前设备会先显示本地结果；
- 浏览器网络挂起或远端暂时不可用时，系统会延后拉取和推送，而不是立刻把本地状态清掉；
- 推送失败的本机记录会进入待同步或死信流程，方便之后恢复。

预览失败也不会阻塞任务本身。桌面悬浮预览的错误态明确写着：任务仍可继续操作，也可以直接打开思源原块。

### 多设备时什么会同步，什么不会

会同步的是：

- 锚点指针本身；
- 指针的轻量元数据；
- 导出、导入和灾备里的锚点记录。

不会跨设备同步的是：

- 思源 token；
- Relay 本地配置；
- 当前设备的预览缓存正文；
- 只对当前设备有意义的临时状态。

所以多设备的正确预期应该是：

1. **同账号已登录设备**：同步完成后，应能看到同一个锚点指针。
2. **另一台新设备**：即使看到了锚点，也不代表已经能实时预览；它仍需要自己的本机授权或自己的缓存。
3. **本地离线模式**：当前实现不会走远端 `external_source_links` 拉取和推送，这时不要预期锚点自动出现在别的设备。

### 更换设备或清浏览器数据前先做什么

如果你准备换设备、清站点数据或做大规模排障，先做这几件事：

1. 导出当前项目 JSON；
2. 保留本地或灾备副本；
3. 再处理浏览器数据、扩展或授权。

当前导出、导入和灾备都已经覆盖 `externalSourceLinks` 指针，但不会把 token 或预览正文缓存打包进去。导入时，系统还会重新校验思源块链接；非法锚点会被跳过，不会强行导入成脏数据。

## 失败时看什么、先做什么

### 预览错误文案怎么理解

当前错误码会映射成这些用户可见提示：

| 文案 | 代表什么 | 第一动作 |
| --- | --- | --- |
| `当前设备未配置思源，仅可打开原块` | 这台设备没有可用授权 | 继续做任务，等方便时去设置 |
| `当前环境不支持实时预览` | 当前运行环境不支持实时抓取 | 改用打开原块，或切回支持的桌面环境 |
| `安装 NanoFlow 扩展后可实时预览` | 预览需要扩展，但当前没有可用扩展 | 处理设备环境，或先接受只开原块 |
| `未连接到思源，请确认思源已启动` | 本机思源内核不可达 | 先确认思源是否已启动 |
| `思源授权失效，请重新配置` | token 不可用 | 在当前设备重新授权 |
| `原块可能已删除或移动` | 指向的块已经不存在或不再匹配 | 在思源里找到新块后替换关联，或直接解除关联 |
| `预览内容包含不支持或不安全内容` | 预览被安全渲染链路拦住 | 直接打开原块查看，不要强行绕过 |
| `预览失败，可稍后重试` | 未归类错误 | 先保留当前任务，稍后刷新或打开原块 |

### 常见异常和恢复动作

| 你看到的现象 | 先不要做什么 | 先做什么 |
| --- | --- | --- |
| 粘贴后提示 `思源链接无效` | 不要反复粘贴网页 URL、文件路径或整段文字 | 回到思源重新复制块链接，或只贴块 ID |
| 点击后提示 `思源链接无效` / `已阻止打开非 siyuan:// 块链接` | 不要继续信任这条旧链接 | 进入替换关联，或解除关联后重建 |
| 提示 `浏览器已拦截弹窗，请在原块上右键打开` | 不要以为 NanoFlow 页面已经坏了 | 先处理浏览器弹窗限制；应用自身状态不会被这个动作替换掉 |
| 预览一直失败，但任务还在 | 不要把任务正文复制成思源全文临时兜底 | 直接打开原块继续工作，之后再排查授权或内核状态 |
| 刚在一台设备改完，另一台设备没看到 | 不要马上两边同时继续改 | 先确认同账号、等待同步稳定，再在另一台核对 |
| 准备清浏览器数据来“重装试试” | 不要先清再说 | 先导出数据和备份，再处理站点数据 |

### 设置页里的恢复动作分别干什么

| 按钮 | 会做什么 | 不会做什么 |
| --- | --- | --- |
| `测试连接` | 诊断当前模式能否连通思源或扩展 | 不会自动帮你安装扩展 |
| `清除本机缓存` | 删除当前账号当前设备上的思源预览缓存 | 不会删除锚点本身 |
| `忘记本机授权` | 删除本机侧的思源授权；Relay 模式下还会尽量通知扩展清 token | 不会删除云端锚点指针 |
| `保存到扩展` | 把当前页面输入的 base URL / token 写到扩展 | 不会把 token 存回 NanoFlow 页面持久化存储 |

如果扩展配置通道太旧，设置页会明确告诉你去更新扩展或去扩展 `Options` 页面处理。那是环境修复，不是锚点内容修复。

## 隐私与信任边界

当前实现有几条很明确的边界：

1. **思源是知识源头**。NanoFlow 主要保存的是锚点指针，不是思源正文镜像。
2. **Relay 模式下页面不留存 token**。页面只把 token 暂存在内存，点击 `保存到扩展` 后立即清掉。
3. **Direct 模式只信任本机 localhost/127.0.0.1**。它不是拿来连任意远端地址的。
4. **本机预览缓存不进云端**。这也是为什么一台设备有预览，不代表另一台也一定有。
5. **打开原块时只允许合法 `siyuan://` 块链接**。无效链接会被拦住，不会直接放行。

如果你对隐私要求更高，至少要记住这件事：多设备之间同步的是“这项任务指向哪个思源块”，不是“这台设备的授权和缓存也一起过去”。

更完整的边界说明见 [安全与隐私](../03-data-sync-safety/04-security-and-privacy.md)。

## 常见问题

### 删除锚点会删除思源里的原块吗？

不会。当前实现只会解除 NanoFlow 和该块的关联，并删除当前设备上这条关联对应的预览缓存。

### 我能在 NanoFlow 里直接改思源正文吗？

不能。当前能力是只读预览、打开原块、刷新缓存、替换关联和解除关联。

### 为什么我在某些地方只看到“打开思源”，看不到完整预览？

因为不同上下文使用的预览模式不同。Parking Dock 当前就是 `deep-link-only` 紧凑模式；只读上下文也可能只显示第一个锚点。

### 为什么另一台设备能看到锚点，却看不到实时预览？

因为锚点指针会同步，但 token、扩展配置和本机缓存不会。另一台设备需要自己的本机授权，或者它自己此前已经缓存过该块预览。

### 我可以把远端自建思源地址填进 direct 模式吗？

当前不能。源码只信任 `http://127.0.0.1:6806` 和 `http://localhost:6806`，而且页面本身也必须是本机页面或 `file:` 页面。
