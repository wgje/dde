# 思源知识锚点

思源知识锚点用来把 NanoFlow 任务连接到思源里的知识块。它的目标不是把 NanoFlow 变成第二个知识库，而是让任务能指向资料来源，同时继续保持任务本身的执行属性。

## 什么是知识锚点

一个知识锚点通常指向思源块，例如：

```text
siyuan://blocks/{blockId}
```

NanoFlow 保存的是轻量指针和展示元数据，而不是整篇思源正文。这样可以避免：

- 同一份资料在两个地方维护；
- 任务正文变成超长知识笔记；
- 同步大量不必要正文；
- 移动端打开任务时加载过重。

## 适合保存哪些信息

适合放在锚点里的信息：

- 思源块 ID；
- 块标题或路径；
- 标签；
- 来源角色；
- 本机缓存预览；
- 回跳链接。

任务正文里应该保留执行信息，例如“下一步做什么”“验收标准是什么”。资料正文仍然留在思源维护。

## 桌面端预览方式

桌面端可能有三种模式：

| 模式 | 含义 | 适合场景 |
| --- | --- | --- |
| extension-relay | 浏览器扩展帮助 NanoFlow 安全访问本机思源 | 推荐桌面实时预览 |
| direct | 浏览器环境允许时直接访问本机思源 | 本地测试或受控环境 |
| cache-only | 只使用本地缓存的预览信息 | 无法实时连接时兜底 |

如果 HTTPS PWA 不能直接访问 `127.0.0.1:6806`，优先使用扩展 Relay，而不是关闭浏览器安全限制。

## 移动端和弱连接环境

手机或公网 PWA 环境通常不能直接访问桌面思源内核。这时应该：

- 保留锚点；
- 显示已有元数据；
- 尝试深链回跳思源；
- 不因为预览失败阻塞任务执行；
- 不把思源 token 同步到云端。

本机凭证和预览缓存应只属于当前设备。

## 推荐使用方式

建议：

1. 长文、资料、研究记录继续放思源。
2. NanoFlow 任务只写执行动作。
3. 每个任务只挂最相关的块，不要随便挂整个文档根。
4. 如果任务需要多个资料来源，给每个锚点写清楚角色。
5. 移动端看不到实时预览时，用深链回跳，不要复制长文进任务正文。
