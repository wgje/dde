# Focus 专注模式

Focus 当前实现的核心不是“再造一份任务清单”，而是先用 Gate 把待判断输入清掉，再回到原来的任务视图继续做事。真正会自动维护、会跟随同步刷新的，是 Gate 审查队列和 Strata 历史层。

## 先认识当前实现里的 4 个面板

| 概念 | 含义 | 使用建议 |
| --- | --- | --- |
| Gate | Focus 入口的审查层 | 进入专注前先处理这里的待决条目 |
| Black Box | 快速收集箱 | 文字和语音都先落这里，再决定去向 |
| Gate 队列 | 当前正在审查的 Black Box 待处理条目 | 这是当前实现里最明确、最自动化的 Focus 队列 |
| Strata | 已完成任务和已完成 Black Box 的分日历史层 | 只在要“挖回”旧内容时展开 |

## Gate 什么时候出现

当前实现里，Gate 不是每次打开 Focus 都强制出现。它按下面的顺序判断：

1. 先读本地黑匣子数据，先让界面可用，不为等云端阻塞首屏。
2. 如果 `gateEnabled` 关闭，Gate 直接进入 `disabled`，不会弹出。
3. 如果当前设备/浏览器已经为当前账号记住“今天处理过 Gate”，当天再次进入 Focus 通常会直接 `bypassed`。
4. 只有 `gateEnabled` 开启且存在待处理 Black Box 条目时，Gate 才进入 `reviewing`。
5. 本地检查后还会延迟做一次远端补拉；所以 Gate 可能先按本地结果出现，稍后再跟云端结果对齐。

你可以把 Gate 的可见状态理解成这样：

| 状态 | 代表什么 | 你该怎么理解 |
| --- | --- | --- |
| `disabled` | 你关掉了 Gate | 进入 Focus 时不会先审查输入 |
| `reviewing` | 有待处理条目 | 这是当前需要逐条做决定的入口 |
| `completed` | 队列真的清空且当前动作已经落稳 | 会短暂显示完成反馈，然后关闭 |
| `bypassed` | 当前没有待处理条目，或同设备今天已处理过 | 不代表 Black Box 被删除，只代表这次不再弹门 |

此外，页面回到前台且离开时间超过 5 分钟时，Focus 会再做一次 Gate 检查。你在电脑或手机上切出一段时间再回来，看到 Gate 重新判断，是当前实现的正常行为。

## Gate 里每张卡怎么处理

Gate 里的每一张卡，本质上都是一条待判断的 Black Box 条目。当前新门体最稳定、最明确的动作是：

| 动作 | 当前实现 | 你该怎么用 |
| --- | --- | --- |
| 标记已读 | 让当前卡离开当前审查步骤，但条目仍保留为 Black Box 条目 | 适合“我看过了，但现在不把它算完成” |
| 标记完成 | 把条目标记为完成并移出当前 Gate 队列 | 适合已经明确处理完、以后只需要在历史里回看 |
| 快速补录 | Gate 内支持快速语音/手动补录 | 适合发现还缺一句说明时就地补进 Black Box |

当前键盘快捷键：

- `1` 或 `Enter`：标记已读
- `2` 或空格：标记完成

Gate 代码里仍保留了 Snooze 兼容路径和“每天最多 3 次”的上限，但当前新门体不把它当主要入口来暴露。日常使用里，优先把条目处理成“已读 / 已完成 / 转去 Black Box 补录”。

Gate 内的语音补录也遵循和 [Black Box 黑匣子](05-black-box.md) 一样的确认规则：

1. 长按录音区域开始录音。
2. 在录音区域内松开，才会停止并转写。
3. 手指或鼠标拖出录音区再松开，会直接取消，不保存半成品。
4. 转写结果会先进入可编辑预览，确认后才真正写入 Black Box。
5. 浏览器不支持录音或录音启动失败时，会退回手动文字补录，而不是把整个 Gate 卡死。

## Gate 队列为什么不会乱跳

Gate 在 `reviewing` 期间，不是只看一份静态列表。当前实现会同时接收三类刷新来源：

- 首次 `checkGate` 的本地判断；
- 本地待处理条目变化时的信号刷新；
- 页面可见时的远端补拉和定时拉取。

这意味着你在另一台设备上改动 Black Box 后，当前设备里的 Gate 可能在审查中途刷新。但它不会因为一次远端“空队列”结果就立刻把当前卡抽走：

- 如果你当前卡的动画或落库还没完成，Gate 会保留这张卡；
- 如果远端第一次回空，但当前卡还处在“本地可能刚提交”的窗口里，Gate 会先等确认，不会立刻判定队列清空；
- 只有队列真的空了，而且当前动作已经完全落稳，Gate 才会进入 `completed` 并关闭。

这就是为什么遇到“我刚点完，卡片还停了一下”时，不应该立刻重复点第二次。先等当前动作完成，状态通常会自行收敛。

## 当前实现里的 Focus 队列到底是什么

这份手册里的“Focus 队列”，在当前实现里首先指 Gate 正在维护的那条审查队列，也就是 `gatePendingItems`：

- 它只装还没处理完的 Black Box 条目。
- 它会保留你已经看到但正在动画/落库中的当前卡。
- 它会随着本地变化和远端刷新自动合并。

Focus 不会自动复制出“今天全部任务的一份平行清单”。项目任务本身仍然在原来的文本/流程视图、停泊坞和其他面板里管理。Gate 清完以后，你回到的还是原来的任务系统，不是第二套 backlog。

## Strata 怎么看和怎么恢复

Strata 是按天堆叠的历史层，当前实现有几个很实用的特点：

- 默认最多显示最近 30 天。
- 顶部摘要会显示“本周多少项”“累计多少天 / 多少项”。
- 越新的层默认展示越多：最近 3 层默认展示 8 项，第 4 到第 7 层展示 5 项，更早的层展示 3 项。
- 某一天条目太多时，可以只展开那一天，不会把整页历史一次性全部摊开。

最重要的是“恢复”动作的语义：

| 从 Strata 恢复什么 | 当前实现会做什么 |
| --- | --- |
| 已完成任务 | 把任务状态恢复成 `active`，回到当前工作流里 |
| 已完成 Black Box 条目 | 取消 `isCompleted`，让它重新回到可继续处理的状态 |

所以 Strata 更像“可挖回的历史层”，不是只读档案馆。恢复前最好先确认：你现在是否真的要重新处理这条内容。

## 设置、今日状态和跨设备

Focus 偏好（例如 Gate、Black Box、Strata 开关）采用“本地立即生效，云端异步同步”的策略：

- 改动后先写当前浏览器的 `localStorage`，所以本机立刻生效；
- 已登录时再异步写到云端，不阻塞当前界面；
- 云端返回较旧偏好时，不会覆盖更新的本地设置，按 `updatedAt` 做新旧判断。

这带来两个很重要的边界：

1. 偏好本身可以跨同一账号同步到其他设备。
2. “今天这个设备上的 Gate 已处理过”不走云端，它按当前账号保存在本机 `localStorage`。也就是说：
   - 同一设备/浏览器今天处理完 Gate 后，再次进入 Focus 通常不会再弹；
   - 另一台设备是否再弹 Gate，要看它自己的本地状态和拉到的数据；
   - 这不是数据丢失，只是入口去重是按设备本地算的。

| 设置 | 对 Focus 的影响 | 使用建议 |
| --- | --- | --- |
| Gate | 决定进入 Focus 时是否先走审查层 | 关闭后不会删 Black Box，只是跳过 Gate 入口 |
| Black Box | 决定是否保留快速收集入口 | 关闭入口不等于删除已有记录 |
| Strata | 决定是否显示历史沉积层 | 只在需要回看或恢复历史时打开 |
| 高负荷/低负荷提醒 | 控制提醒节奏 | 只影响提醒，不改 Gate 和 Black Box 数据 |

这些开关本身只更新偏好，不会删除任务、Black Box 记录或停泊项。视觉或入口没有按预期变化时，先确认对应功能是否已启用、当前会话是否完成启动，再回到文本视图确认原始任务仍在；不要反复切换开关或清浏览器数据。

日常任务槽也使用同一组偏好中的本地重置时间来判断“今天”的完成次数。它的完整操作说明在 [Parking Dock 停泊坞](03-parking-dock.md#日常任务槽和逻辑日切)。

## 专注入口异常时怎么恢复

如果 Gate、Strata 或 Focus 入口看起来和你预期不一样，按下面的顺序排查：

1. 先确认当前会话已经完成启动和登录恢复。Focus 会先做本地加载，再做延迟远端补拉。
2. 如果今天在这台设备上已经处理过 Gate，不要反复切换 Gate 开关试图“强行再弹”。先直接打开 [Black Box 黑匣子](05-black-box.md) 看原始条目。
3. 如果你刚从后台回来，先把页面保持在前台一小会儿。离开超过 5 分钟后，Focus 会重新检查 Gate；手机端 Black Box 抽屉在重新可见时也会刷新一次。
4. 如果刚在另一台设备处理过条目，先等当前设备完成可见态刷新，再判断是否真的不同步。
5. 如果刚点完 Gate 动作，先等当前卡片动画和保存完成，不要连续快速点击。
6. 如果看到条目仍然带着 `待同步` 或 `需确认`，这时问题已经不只是 Gate 入口，而是同步状态，直接看 [同步与冲突处理](../03-data-sync-safety/02-sync-and-conflicts.md)。

Focus 只是入口和历史层，不替代原始任务数据。怀疑入口异常时，原任务、Black Box 原条目和同步状态始终比“再点一次 Focus”更值得先检查。

## 限制和注意事项

| 项目 | 当前规则 |
| --- | --- |
| Gate 每日打盹上限 | 3 次（兼容路径保留，当前新门体不把它当主入口） |
| 重新检查 Gate 的待机阈值 | 页面回到前台且离开超过 5 分钟 |
| Strata 展示范围 | 最近 30 天 |
| 语音转写额度 | 每日 50 次，详见 [Black Box 黑匣子](05-black-box.md) |

如果你发现自己想把大量长期任务都塞进“Focus 队列”，那通常说明该回到任务视图、停泊坞或 Black Box 做整理了。当前实现里，Focus 更适合做入口审查和历史恢复，不适合承担完整计划管理。
