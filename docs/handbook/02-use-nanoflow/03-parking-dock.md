# Parking Dock 停泊坞

Parking Dock 用来处理一种很常见的状态：这件事还重要，但现在不该占用当前任务列表。它既不是删除，也不是归档，而是“暂时停一下，之后还要回来”。

## 什么任务应该停泊

适合停泊的任务：

- 等别人回复；
- 等某个日期再处理；
- 当前不做，但怕忘；
- 和当前 Focus 无关，但未来仍重要；
- 暂时缺资料，不能继续推进；
- 今天的注意力范围太满，需要挪开。

不适合停泊的任务：

- 已经没价值的任务，应该删除；
- 已经完成且长期不用看的任务，应该归档；
- 今天马上要做的任务，应该留在当前任务列表或 Focus；
- 没有任何行动价值的想法，应该从 Black Box 里丢弃。

## 停泊任务时要写清楚什么

停泊不是把任务扔进一个黑洞。停泊时最好补充：

| 信息 | 示例 |
| --- | --- |
| 为什么停泊 | `等张三确认合同版本` |
| 什么时候再看 | `周五下午复查` |
| 回来后第一步做什么 | `打开对方邮件，确认附件是否更新` |
| 当前卡点 | `缺少报价单` |
| 是否重要 | `高优先级，不能超过本周` |

如果界面支持提醒、备注或 pin，就尽量填清楚。未来的你不应该重新猜“当时为什么停泊”。

## 如何恢复停泊任务

当任务重新变得可执行：

1. 打开 Parking Dock。
2. 找到对应任务。
3. 看停泊备注，确认为什么它当时被停泊。
4. 如果已经可以做，恢复到任务列表或送入 Focus。
5. 如果仍然不能做，更新备注或提醒时间。
6. 如果已经没价值，走删除或归档路径。

恢复后建议立刻补充任务正文，写下新的下一步。

## 停泊、归档、删除、Focus 的区别

| 操作 | 意味着什么 | 适合场景 |
| --- | --- | --- |
| 停泊 | 之后还要回来处理 | 等回复、等时间、暂时挪开 |
| 归档 | 长期不活跃，但保留记录 | 完成、过期但要留痕 |
| 删除 | 从当前工作中移除 | 无价值、重复、测试任务 |
| Focus | 当前时段要集中处理 | 今天或此刻真正要推进 |

如果你只是“不想现在看到它”，优先考虑停泊；如果你确定不再需要，才删除或归档。

## 使用建议

- 每天开始工作前看一眼停泊坞，确认有没有到期或高优先级任务。
- 不要把 Parking Dock 当成永久仓库。
- 停泊任务太多时，说明你需要做一次整理，而不是继续停泊。
- 高风险任务停泊前，先在正文里写清楚当前状态。
- 已经同步到云端的停泊状态，也要注意多设备编辑可能产生覆盖。
