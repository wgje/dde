# Black Box 黑匣子

Black Box 是当前实现里最稳定的“先收进去，再决定去向”的入口。它支持文字速记、长按录音、Gate 内快速补录、离线缓存和后续复盘，但每一条输入都要回到可判断的状态，不能把它当永久堆放区。

## Black Box 适合记录什么

适合放进 Black Box：

- 突然想到的任务；
- 一句临时想法；
- 会议中来不及整理的要点；
- 语音速记；
- 不确定是否值得处理的内容；
- 当前工作之外的提醒。

不适合长期留在 Black Box：

- 已经明确要做的任务；
- 长篇资料；
- 需要多步推进的项目；
- 已经没意义的噪声；
- 应该进入知识库维护的正文资料。

## 现在有哪些录入方式

当前实现里，Black Box 至少有这几条常用入口：

| 入口 | 适合什么场景 | 你实际会怎么操作 |
| --- | --- | --- |
| 文字输入 | 最稳、最直接 | 输入内容后点“保存”；聚焦输入框时可用 `Ctrl+Enter` 或 `Cmd+Enter` 提交 |
| 录音按钮 | 说得比打得快时 | 长按开始，松开后转写 |
| Gate 内快速补录 | 审查 Gate 时发现信息不够 | 就地补一句，不必先退出 Focus |
| 不支持录音时的降级输入 | 浏览器或设备拿不到录音能力时 | 直接切到文字输入，界面会给出“当前浏览器不支持录音，请使用文字输入”的提示 |

文字输入当前有 10000 字符上限，适合“先落点，再分流”。如果你已经知道它是正式任务，后面还是要回到任务系统补标题、状态和下一步。

## 语音录入的真实流程

无论你是在 Black Box 面板里录，还是在 Gate 里快速补录，当前实现的录音流程都遵循同一套规则：

1. 长按录音区开始录音。
2. 只要还在录音区内，松开就会停止并转写。
3. 手指或鼠标拖出录音区再松开，会直接取消录音，不会生成条目。
4. 转写结果不会立刻写入 Black Box，而是先进入可编辑预览。
5. 你确认预览后，文本才真正保存为一条 Black Box 记录；取消预览则不保存。

这几个限制也要提前知道：

- 语音转写要求当前有有效登录会话；未登录时会直接报认证失败。
- 当前每日语音转写额度是 50 次。
- 录音按钮一次只允许一个录音/转写过程在途。正在转写时，新的录音不会并发开始。
- Gate 内录音拿不到浏览器支持或启动失败时，会直接打开手动文字补录，而不是硬失败。

## 录完以后怎样复盘和处理

Black Box 面板和移动抽屉当前是“本地先可见，再做远端刷新”的工作方式：

- 面板打开时，会先把本地快照显示出来；
- 然后再做一次轻量远端刷新；
- 手机端在页面重新回到前台时，还会再补拉一次，尽量把电脑端的新修改带回来。

单条记录当前支持这些动作：

| 动作 | 结果 |
| --- | --- |
| 标记已读 | 记录还在，但表示你已经看过 |
| 标记完成 | 记录离开当前待处理列表，进入 Strata 历史层 |
| 删除 | 记录走删除路径，不再作为当前输入出现 |
| 从 Strata 恢复 | 已完成任务恢复成 `active`；已完成 Black Box 取消完成标记 |

当记录项获得焦点时，键盘也可直接操作：

- `r`：标记已读
- `c`：标记完成

复盘时，推荐按这个顺序做判断：

1. 是明确动作，就转成任务或挂到已有任务。
2. 是已经处理完的输入，就标记完成。
3. 是噪声或重复，就删掉。
4. 是历史上做完、现在又要继续的内容，就从 [Focus 专注模式](04-focus-mode.md#strata-怎么看和怎么恢复) 里的 Strata 恢复回来。

## 怎么看同步状态

Black Box 条目自身有两种最重要的同步提示：

| 提示 | 当前实现含义 | 你该怎么做 |
| --- | --- | --- |
| `待同步` | 这条记录已经本地保存，但云端还没确认；本地模式用户不会显示这个标记 | 先不要重建同一条记录，等同步自己收敛 |
| `需确认` | 当前条目进入冲突/确认状态 | 先停下在多台设备上继续改同一条，去看同步与冲突处理 |

如果你还会看侧边栏的全局状态点，当前颜色含义是：

| 颜色 | 代表什么 |
| --- | --- |
| 蓝色 | 正在同步 |
| 绿色 | 当前没有明显同步问题 |
| 黄色 | 离线、未登录、有待同步项，或云同步处于暂停态 |
| 灰色 | 正在后台重试 |
| 红色 | 有死信、队列冻结、冲突、同步错误或遗留审查项 |

看见 `待同步` 时，优先理解为“已保存，待上云”；看见 `需确认` 或红色状态，再去读 [同步与冲突处理](../03-data-sync-safety/02-sync-and-conflicts.md)。

## 离线录音、占位文字和自动恢复

当前实现对语音失败不是简单报错退出，而是分成两类处理：

1. **可重试错误**：例如网络暂时不可用、浏览器恢复连接中、上游要求稍后再试。
   - 系统会尝试把音频缓存到本地。
   - 录音区可能先返回一段占位文字，例如 `[离线录音，稍后转写]`。
   - 这不是最终转写结果，只表示音频已经保住，后面会尝试重放。
2. **永久拒绝错误**：例如某段离线音频被转写服务判定为不可继续重试。
   - 该音频会被隔离，不再自动重试。
   - 隔离不是删除，音频仍留在本机缓存里，只是为了避免它一直堵住后续健康录音。

离线自动恢复还有几个边界，最好提前知道：

- 自动重放只会把录音写回原来的账号。你中途切换账号时，旧录音不会自动灌进新账号。
- 没有 owner 元数据的旧缓存录音会被隔离，不会自动转写到任何账号。
- 离线重放是分批做的。缓存很多时，不保证一次联网就全部清空，系统会继续安排下一批。
- 如果离线缓存里的转写重新落库失败，音频会继续留在缓存里，等待下次重试。

所以遇到“刚联网但离线录音没有瞬间全部变成文字”时，先不要重复录入同一段内容。先保持同一账号在线一会儿，让重放批次跑完。

## 跨设备时应该期待什么

同一账号下，Black Box 的数据和偏好会跨设备对齐，但不是所有状态都同步得一模一样、同一时刻出现：

- 电脑端改完 Black Box，手机端通常要等抽屉打开或应用回到前台后再补拉一次；
- Gate 审查中的设备会在页面可见时定时补拉，所以另一台设备的修改可能在你审查中途出现；
- 同一账号的偏好开关可以跨设备同步，但离线音频缓存、录音隔离状态和“这台设备今天是否处理过 Gate”属于本机状态。

最稳妥的预期是：**数据会汇合，入口时机会因设备而不同。**

## 常见故障先看哪里

| 现象 | 先检查什么 |
| --- | --- |
| 录音根本起不来 | 麦克风权限、浏览器是否支持录音；不支持时直接改用文字输入 |
| 只看到 `[离线录音，稍后转写]` | 这表示音频已缓存，不是最终文字；保持同一账号在线，等自动重放 |
| 条目一直显示 `待同步` | 先不要重建重复条目；等网络恢复、面板重开或前台刷新后再看 |
| 条目显示 `需确认` | 停止在多台设备并行改同一条，转去同步/冲突文档处理 |
| 提示“录音已隔离” | 这段音频不会再自动重试，但仍保留在本机缓存 |
| 手机上看不到电脑端刚改的记录 | 先把应用切回前台或重新打开抽屉，触发一次视图刷新 |

更细的语音排障见 [transcribe-troubleshooting.md](../../transcribe-troubleshooting.md)。

## 不要长期堆积

Black Box 堆积过多会带来两个直接问题：

1. 真正重要的记录被噪声淹没。
2. 进入 Focus 时，Gate 审查成本会越来越高。

建议：

- 每天至少清一次 Gate。
- 每条记录尽量在 24 小时内处理。
- 不要把完整文章、长资料或正式项目计划长期堆在这里。
- 语音转写失败时，先看状态和缓存恢复，不要连续重复提交同一段录音。
