# 同步诊断与冲突中心

当 NanoFlow 显示待同步、失败操作、同步暂停或数据冲突时，先不要把它们都当成“网络坏了”。系统仪表盘、同步状态区和冲突中心分别提供了可观察的状态、队列和恢复选择。正确顺序是：确认当前项目和账户，保留现场，做一次有针对性的重试，再决定是否重新同步或解决冲突。

本页是“同步出现异常时怎么操作”的使用手册；同步模型和 LWW 原理见 [同步与冲突处理](02-sync-and-conflicts.md)，备份与事故恢复见 [备份与恢复](03-backup-and-restore.md)。

## 什么时候打开系统仪表盘

遇到下面任一情况时，打开界面中的“系统仪表盘”或同步状态入口，而不是直接刷新或清浏览器数据：

- 待同步数量长时间不减少；
- 出现“同步错误”“本地数据可用，登录后继续云同步”或“连接中断”；
- 另一台设备的任务、关系或停泊状态没有出现；
- 同步状态区显示失败操作或严重滞后；
- 看到冲突计数、冲突提醒，或被要求在本地/云端之间选择；
- 当前项目刚从离线恢复、导入或大量批量操作；
- 浏览器提示存储受限、队列冻结或只能导出待同步数据。

进入仪表盘前先确认：当前账号正确、当前项目正确、你没有在另一台设备同时编辑同一批任务。诊断并不会自动替你选可信来源，错误项目或错误账号下的“修复”会扩大问题。

## 读懂状态、队列和冲突标签

系统仪表盘通常按“状态”“冲突”“队列”组织。先看状态，再进入有计数的标签页。

| 位置 | 看到什么 | 正确理解 |
| --- | --- | --- |
| 状态 | 正在同步、离线、登录后继续云同步、同步错误、已保存到云端 | 它描述当前可观察的同步阶段，不是对所有历史数据的绝对证明 |
| 待处理操作 | 尚未完成的创建、更新或删除操作数量 | 网络恢复后会自动尝试；可以在确认环境正确后手动“立即同步” |
| 冲突 | 本地与云端存在不能直接收敛的项目或任务 | 需要判断哪一边可信，或按任务选择/合并 |
| 队列 | 待处理操作和失败操作的明细 | 用于区分“还在等”与“已经失败” |
| 失败操作/死信 | 已经失败并需要人工注意的动作 | 不能只等待；先看动作类型、时间和错误，再重试或保留记录 |

“待同步”并不必然代表数据已经丢失，“死信”也不等于项目一定坏了。两者的关键差别在于：待同步仍有正常重试路径，死信表示某次操作已经失败并需要你决定下一步。

## 待同步、失败操作和队列冻结的区别

### 待同步

待同步表示本机已经接受了操作，但云端尚未确认。常见原因是临时离线、登录尚未恢复、网络不稳定或后台正在处理。

安全动作：

1. 保持当前账号和项目不变。
2. 等网络恢复和后台同步一小段时间。
3. 确认刚改的任务仍在本机。
4. 待同步仍不减少时，再使用“立即同步”或打开仪表盘查看队列。

不要为了让计数消失而反复编辑同一字段、刷新多次或换设备继续改。

### 失败操作和死信

死信队列会显示失败操作，例如创建、更新、删除任务或项目。单条记录可以重试或忽略，多个记录可以在界面中清空。

处理顺序：

1. 看操作类型、对象和失败时间，确认它是不是你刚刚的关键操作。
2. 对网络、会话或短暂服务问题，优先重试一次。
3. 重试后确认任务树、正文、关系或项目状态是否真的变化。
4. 对不再需要的旧操作，先确认它不会覆盖当前可信数据，再选择忽略。
5. 只有已经导出、确认记录无价值且不需要继续诊断时，才清空死信记录。

“忽略”或“清空全部”会移除失败记录的恢复入口，不会自动把原本想做的业务操作改为成功。不要用清空队列代替验证项目数据。

### 队列冻结或存储受限

队列冻结表示本机持久化不能继续可靠处理。界面可能显示仍只存在内存中的操作，并提供“导出待同步数据”。这比普通待同步更严重。

此时应当：

1. 停止批量编辑、导入、删除和切换账号。
2. 立即使用“导出待同步数据”保留现场。
3. 同时导出正常的项目 JSON；有附件时导出附件 ZIP。
4. 记录冻结原因和待处理数量，再检查浏览器存储空间、权限或设备问题。
5. 不要在未导出前清缓存、清站点数据或重新安装浏览器。

## 安全重试和重新同步的顺序

仪表盘提供两类不同动作：重试队列与重新同步当前项目。不要把它们混为同一按钮。

| 动作 | 适用场景 | 不适用场景 |
| --- | --- | --- |
| 立即同步/重试全部 | 网络刚恢复、待同步操作仍在队列、失败原因可能是临时会话或服务问题 | 已知本地与云端有不同版本，但尚未备份和判断可信来源 |
| 重试单条失败操作 | 你能确认这条操作仍然应该执行 | 不清楚它是否会覆盖新数据或删除当前需要的对象 |
| 重新同步当前项目 | 数据看起来旧、另一台设备已有可信更新、需要重新拉取并智能合并 | 当前项目仍在大量未确认编辑、你不知道本地还是云端可信 |
| 清空/忽略失败记录 | 已保存证据且确认这条操作不需要再执行 | 想“先让红色提示消失” |

建议的实际顺序：

1. 导出当前 JSON，尤其是准备改变同步方向前。
2. 在仪表盘看待处理和失败操作；先解决明显的登录、网络或暂停原因。
3. 只做一次“立即同步”或单条重试。
4. 如果另一台设备有明确可信来源，再对当前项目执行重新同步。
5. 重新同步提示发现冲突时，进入冲突标签或冲突中心，不要继续重复点同步。
6. 冲突解决后，检查当前项目的任务数量、关键正文、关系、停泊状态和附件入口。

重新同步会尝试智能合并，而不是简单粗暴地全量覆盖；但“智能”不等于能理解你的业务意图。冲突出现时仍需要你决定哪一边可信。

## 手动冲突模式下的工作方式

当系统设置中的“自动解决冲突”关闭时，冲突中心更频繁出现是正常预期，不代表同步已经失效。同步仍会保存、拉取和记录冲突；不同之处是系统不会替你直接用 LWW 结束这一轮选择。

在这个模式下，不要把“冲突数量出现”当作需要立刻清零的告警。先确认当前账号和项目，导出关键项目，再按下一节逐项选择。完成重要导入、恢复或双设备离线编辑的检查后，才决定继续保持手动模式还是重新开启自动解决。该开关目前只保存在当前浏览器，换设备时需要分别确认。

## 怎样在冲突中心做选择

冲突中心会显示本地和云端的差异、冲突原因、系统建议以及可选的处理方式。常见原因包括云端版本较新、云端已删除和版本不匹配。

先在冲突卡片上确认：项目名、冲突原因、两侧任务数量、最近修改时间和关键任务内容。然后选择下面其中一种明确策略。

| 选择 | 实际含义 | 只有在什么情况下使用 |
| --- | --- | --- |
| 保留本地/本地覆盖云端 | 保留本机修改，并让它成为新的云端方向 | 你确认这台设备保存了最新、完整、可信的工作 |
| 采用云端版本 | 放弃本机尚未同步的修改，使用云端版本 | 你确认另一台设备或云端才是最新正确来源 |
| 合并并保留两边修改 | 尝试保留两侧可合并内容 | 两边都有真实价值，且你愿意在完成后逐项检查 |
| 应用系统建议 | 采用系统的逐任务建议，并包含你已经明确选定的项目 | 你已审阅建议，所有需要人工确认的任务都已作出选择 |
| 稍后解决 | 不立即提交冲突选择 | 需要先导出、核对另一台设备或向维护者确认 |

冲突处理开始后，同一项目的冲突按钮会暂时锁定，避免重复提交。等待当前操作结束；不要同时在另一台设备修改该项目。

### 使用系统建议前的检查

系统建议可以减少逐项操作，但不替你承担数据判断。应用前：

1. 确认仍有需要手动选择的任务时，先逐项选择本地或云端。
2. 对长正文、删除操作、重要附件和关系图，优先人工核对，不要只看任务数量。
3. 导出当前状态，确保选择错误时有回退材料。
4. 应用后检查每个关键任务，而不是只看“冲突已消失”。

## 没有本地项目的孤立冲突

有时冲突记录仍在本机，但本地项目本身已经不存在。这类“孤立冲突”不能正常执行本地覆盖、云端覆盖或合并，因为缺少本地项目上下文。

界面会只提供丢弃该冲突记录的路径。它适用于你已经确认：本地项目确实不需要、云端也不是要恢复的可信来源、并且已经保存必要证据。丢弃冲突记录不是恢复项目，不会自动找回删除的数据。

不确定时先不要丢弃。导出当前项目/队列数据，确认回收站、备份和另一台设备的状态，再决定。

## 队列冻结时的逃生导出

“导出待同步数据”生成的是队列诊断快照，包含待处理操作、死信队列、冻结状态和冻结原因。它不是普通项目 JSON，也不能代替正常导入恢复；它的价值是保留尚未成功持久化或同步的技术证据。

如果出现存储失败逃生弹窗，弹窗会显示待处理和死信数量，并提供格式化 JSON 的复制或下载。优先下载文件而不是只复制到剪贴板；复制内容适合临时交给维护者，下载文件更适合保留完整现场。无论使用哪种方式，都不要把这个诊断 JSON 当作普通项目备份直接导入。

使用方式：

1. 在队列冻结提示出现时立即导出。
2. 以时间和设备名保存文件，避免覆盖多次故障现场。
3. 同时导出项目 JSON 和附件 ZIP。
4. 把队列快照、错误提示和复现步骤交给维护者；不要直接把包含任务内容的文件公开发送。
5. 在确认备份齐全前，不要清空死信、清理浏览器数据或重新初始化应用。

## 完成诊断后的验证

任何重试、重新同步或冲突选择完成后，至少验证以下内容：

- 仪表盘的待同步和失败操作计数是否符合预期；
- 当前项目是否仍是正确项目；
- 关键任务标题、正文、层级、状态和注意事项是否正确；
- Flow 关系、Parking Dock 状态和 Focus 当前项是否合理；
- 重要附件是否仍出现在正确任务下；
- 另一台设备在同步稳定后是否看到同一结果；
- 是否重新出现冲突、死信或队列冻结提示。

只要其中一项不确定，就保留导出文件并停止进一步批量操作。诊断成功不是“提示变绿”，而是关键业务数据在可信来源中一致。

## 常见问题

### 待同步数量一直不变，应该一直点“立即同步”吗？

不要。先检查网络、登录、云同步暂停原因和死信记录。只做一次明确重试；重复点击会让问题更难区分，也可能和另一台设备的修改交错。

### “清空全部”能修复失败操作吗？

不能。它只移除失败记录，不会让原操作变成成功。清空前先导出并确认这批操作已经不需要重试或不应再执行。

### 该选本地还是云端？

选择你能证明是最新完整工作的一边。不要仅凭“这台电脑就在眼前”决定；对比任务正文、最后修改时间、附件和关键关系，必要时先导出两边。

### 合并是不是完全无风险？

不是。合并会尽量保留两边修改，但长正文、删除、关系和附件仍需要你在完成后人工检查。

### 队列冻结后可以直接重装应用吗？

不要先重装。先导出待同步数据、项目 JSON 和附件 ZIP。重装或清站点数据可能删除本地待处理记录，使恢复证据消失。
