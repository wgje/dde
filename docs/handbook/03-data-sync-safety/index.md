# 数据、同步与安全

这一组文档解释 NanoFlow 如何保存数据、怎样同步、多设备冲突如何理解、什么时候备份、哪些隐私和密钥边界不能碰。正式使用前，至少要读懂“本地已保存”和“云端已同步”不是同一件事。

这里既有给日常使用者的安全操作说明，也有给私有实例操作者的边界说明。它不会承诺所有问题都能靠刷新或重试解决；遇到删除、导入、冲突、队列冻结、权限或浏览器存储异常时，先保全数据和证据，再决定下一步。

## 必须先记住的原则

| 原则 | 含义 |
| --- | --- |
| 本地先写 | 操作先更新本机状态和界面 |
| 后台同步 | 有云端配置时再把变更推送出去 |
| 同步可能排队 | 网络、权限或云端错误会让写入进入重试 |
| LWW 不是智能合并 | 同一实体多端修改可能按时间戳覆盖 |
| 备份不是多余的 | 导出和恢复是防止误操作的最后保护 |
| 密钥不能进前端 | 第三方 API key 和 service role key 必须留在服务端 |

这些原则可以用一句话概括：**先保留可恢复副本，再让系统继续改变状态。** 任何会覆盖、删除、迁移或重建数据的操作，都应该先问“如果下一步判断错了，我靠什么回到现在？”

## 看见异常时先做什么

先区分“状态还没有完成”和“状态已经失败”。这两种情况的安全动作不同。

| 看到的现象 | 第一步 | 第二步 | 何时停止自己操作 |
| --- | --- | --- | --- |
| 当前设备已看到修改，另一台还没看到 | 保持当前浏览器和账号不变，确认是否有待同步状态 | 读离线优先模型并按诊断页检查队列 | 两端都开始改同一条任务时，先停一端并导出 |
| 待同步数量持续存在 | 等待网络/会话恢复后按诊断页检查 | 在安全条件满足时重试或重新同步项目 | 状态变成失败、死信或冻结，或重试不再减少数量 |
| 冲突或 stale 提示 | 记录项目、任务和两端最后可信状态 | 按冲突中心的选择顺序处理 | 不清楚哪边是可信来源，或本地项目已经不存在 |
| 任务、项目或附件似乎消失 | 不要立刻重建同名数据 | 先找回收站、导出和备份恢复路径 | 发现删除、导入或同步覆盖发生在多个对象上 |
| 浏览器提示存储不足、离线数据库异常或修复 | 保留当前页面和导出文件 | 按 PWA/错误恢复页判断可执行的修复 | 修复建议涉及清站点数据，而你还没有可验证备份 |
| 登录失效、权限拒绝或另一账号的数据异常 | 停止继续写入，确认当前账号 | 重新登录后只检查状态，不立即重放大量手工操作 | 涉及 RLS、未知项目、多人账户或生产实例权限 |

“先停止”不是放弃处理。它是防止排障动作本身扩大覆盖范围，让后续恢复仍有一份可信起点。

## 什么时候最容易出问题

常见风险场景：

- 在两台设备离线编辑同一个任务；
- 浏览器里有待同步内容时清理站点数据；
- 批量删除任务前没有导出；
- 导入旧数据后立刻让云同步覆盖；
- 上传附件但 Storage 或 RLS 配错；
- Edge Function 缺 Secret，却反复重试语音转写；
- 把服务端密钥误放进前端环境变量；
- 以为 Black Box 语音一定已经转写成功，提前删除原记录。

## 高风险操作前检查表

在做下面操作前，请先检查：

| 操作 | 先做什么 |
| --- | --- |
| 批量删除 | 导出 JSON，确认恢复入口可用 |
| 导入项目 | 先导出现有项目，避免覆盖后无回退 |
| 清浏览器数据 | 确认本地数据已导出或云端已同步 |
| 换设备 | 在旧设备导出，在新设备确认同步或导入 |
| 改 Supabase schema | 备份数据库，确认迁移和类型生成 |
| 开启附件 | 确认私有 bucket 和权限 |
| 开启语音转写 | 确认 Edge Function、Secret、额度 |

高风险操作结束后，保留操作前后的导出、项目名称、时间和看到的状态提示。它们不是多余的记录：出现跨设备差异、迁移或恢复失败时，这些信息能帮助你判断哪个副本仍可信。

## 哪些时候应先停止操作

出现下面任一条件时，不要继续用“再试一次”掩盖问题：

- 你打算清理浏览器站点数据、卸载 PWA、重装浏览器或换设备，但没有一份刚导出的可打开备份；
- 你正准备导入或恢复，而当前项目的状态还没有导出，或不知道导入会覆盖哪些对象；
- 两台设备对同一任务、项目或附件给出了不同内容，而你无法说明哪一边是最后可信副本；
- 待同步已变为失败操作、死信、队列冻结、权限错误，或连续重试没有缩小待处理数量；
- 你需要输入 service role、第三方私钥、部署令牌或生产数据库权限才能继续；
- 你不确定当前连接的是测试项目还是生产项目。

这时最小的安全动作通常是：导出当前可读数据，截图或记录状态，保留浏览器/账号上下文，然后转到对应诊断、备份或运维文章。不要为了让界面恢复“正常”而先删除证据。

## 处理完后怎样确认结果

处理完成不应只看某个提示消失。根据你做的动作，至少验证下面对应的一项：

| 处理动作 | 最小确认 |
| --- | --- |
| 等待或重试同步 | 待同步/失败数量下降到预期，项目内容在同一账号的另一端可读且没有意外覆盖 |
| 解决冲突 | 你选择的版本仍存在，其他端刷新后不会重新出现同一冲突，且没有把无关任务改掉 |
| 恢复备份 | 项目、任务层级、正文和需要的附件都符合恢复前的目标；恢复后的副本再导出一次以保留新基线 |
| 清理或迁移前备份 | 导出文件能找到、能打开，并且你知道它是否包含附件或本地增强备份数据 |
| 修复 Storage、权限或登录 | 测试账户只能看到自己应有的数据，附件与同步分别通过，不把临时高权限配置留在前端 |

只要验证结果不符合预期，就回到相应专题文章的恢复步骤，而不是继续叠加新的导入、重试或手工补数据。
