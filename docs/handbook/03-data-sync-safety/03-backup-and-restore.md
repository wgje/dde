# 备份与恢复

备份不是等出事后才想起来的功能。只要你准备把真实工作放进 NanoFlow，就应该先知道如何导出、如何恢复、附件和结构数据有什么区别。

## NanoFlow 有哪些恢复层

| 层级 | 能解决什么 | 不能解决什么 |
| --- | --- | --- |
| 回收站/归档恢复 | 普通误删、误归档 | 浏览器数据被清、云端覆盖 |
| JSON 导出 | 项目、任务、结构数据恢复 | 原始附件文件 |
| 附件 ZIP 导出 | 原始附件备份 | 任务结构和状态 |
| 桌面本地自动备份 | 定期保存本机快照 | 不支持的浏览器或被关闭的目录权限 |
| Supabase 备份 | 云端灾难恢复 | 本地未同步内容 |

重要数据至少应该有两层保护：应用内恢复 + 导出或自动备份。

## 什么时候必须备份

以下操作前必须导出：

- 批量删除任务；
- 大规模重排项目结构；
- 导入外部 JSON；
- 清理浏览器数据；
- 换电脑或重装系统；
- 改 Supabase schema；
- 手动修数据库；
- 开启或迁移云同步；
- 处理疑似数据不一致。

如果包含附件，必须同时导出附件 ZIP。只导出 JSON 不等于备份附件文件。

## JSON 导出和附件 ZIP 的区别

| 导出类型 | 包含什么 | 适合做什么 |
| --- | --- | --- |
| JSON | 项目、任务、连接、部分元数据 | 恢复结构、迁移任务数据 |
| 附件 ZIP | 上传过的原始附件文件 | 恢复文件本体 |

恢复时通常先导入 JSON，再导入附件 ZIP。顺序反过来可能导致文件找不到对应任务。

## 普通恢复顺序

遇到误删或数据异常时，按这个顺序：

1. 先停止在其他设备继续编辑。
2. 在当前设备导出一份“出问题后的现状”，防止修复过程更糟。
3. 先检查回收站或归档恢复入口。
4. 找最近一次可信 JSON。
5. 导入 JSON。
6. 如果有附件，再导入附件 ZIP。
7. 打开关键项目，检查任务数量、重要分支、附件和正文。
8. 确认恢复正确后，再让云同步继续。

恢复时一定要选一个设备作为当前可信来源，不要多台设备同时抢着恢复。

## 桌面本地自动备份

桌面自动备份适合 Chrome 或 Chromium 系浏览器。推荐做法：

1. 在设置里选择备份目录。
2. 选择一个会自动同步的目录，例如 OneDrive、Dropbox、坚果云或其他可信目录。
3. 确认备份文件真的生成。
4. 每隔一段时间抽查一次备份文件是否能看到。
5. 换电脑前，确认这个备份目录已经同步完成。

自动备份不是云同步的替代品，但它能防止本机浏览器数据被误清后完全无路可退。

## 恢复时不要做什么

- 不要还没导出当前状态就清浏览器数据。
- 不要在两台设备同时导入不同备份。
- 不要把旧备份导入后马上让另一台设备覆盖它。
- 不要只恢复 JSON 却以为附件也恢复了。
- 不要在不知道 RLS 和 schema 状态时直接手动改数据库。
