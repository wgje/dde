# 开始使用

这一组文档帮你从“第一次打开项目”走到“可以放心创建真实任务”。如果你还没有使用过 NanoFlow，不建议一开始就导入大量数据或开启多设备同步。先用一个小项目跑通本地保存、编辑、恢复和备份流程，再决定是否配置 Supabase。

## 推荐阅读顺序

1. 先读 [快速开始](01-quickstart.md)，确认你能安装依赖并打开应用。
2. 再读 [本地离线模式](02-local-only-mode.md)，弄清楚没有登录和云同步时数据保存在哪里。
3. 然后跟着 [第一个项目演练](03-first-project.md) 创建一个很小的真实项目。
4. 如果你确实需要多设备、附件、语音转写或 Android 小组件，再读 [云同步配置](04-cloud-sync-setup.md)。

## 开始前先理解的边界

NanoFlow 的默认设计是离线优先，因此“没有云服务”不等于“不能用”。你可以先本地创建项目和任务，等确认工作流适合自己后再配置云同步。

但是，本地模式也有明确边界：

- 数据主要跟随当前浏览器、当前浏览器用户资料和当前设备。
- 清理浏览器数据、换浏览器、换电脑前必须先导出。
- 附件、登录、跨设备同步、语音转写、Android 小组件都需要额外云端配置。
- 多设备同时离线编辑同一项任务时，后续同步可能发生覆盖或冲突。

## 第一次使用的安全顺序

建议按下面顺序试用：

1. 只创建一个测试项目。
2. 在项目里创建 3 到 5 个任务，不要一开始导入全部真实数据。
3. 修改任务标题、正文、层级和顺序。
4. 删除一个不重要的任务，再从恢复入口找回。
5. 导出一次 JSON，确认你知道备份文件在哪里。
6. 如果要上传附件，再单独确认附件导出路径。
7. 最后再决定是否配置 Supabase 云同步。

这个顺序能让你在数据量很小时就理解保存、恢复和同步边界，避免后面带着大量真实资料排查基础问题。
