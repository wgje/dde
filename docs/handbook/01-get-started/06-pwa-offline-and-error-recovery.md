## 安装、打开方式与版本更新

### 安装提示代表什么

安装横幅来自 `PwaInstallPromptService` 和 `PwaInstallPromptBannerComponent`。它只在下面这些前提同时满足时才会出现：

- 当前还不是独立窗口或主屏启动模式；
- 你之前没有关闭过安装提示；
- 浏览器当前支持对应的安装入口。

| 你看到的文案 | 这代表什么 | 最稳妥的动作 |
| --- | --- | --- |
| `安装应用` 按钮 | 当前浏览器给了可直接调用的安装提示 | 点一次，等结果返回；安装后从桌面或主屏再打开一遍确认项目还在 |
| `iOS: 在浏览器分享菜单中选择“添加到主屏幕”` | iPhone/iPad 没有一键安装按钮，走系统分享菜单 | 用 Safari 或当前浏览器的分享菜单添加，不要为了让横幅重现去清站点数据 |
| `请使用浏览器地址栏或菜单中的“安装应用/添加到主屏幕”入口` | 浏览器可安装，但当前走原生入口提示而不是 NanoFlow 自己弹按钮 | 直接用地址栏或菜单里的安装入口 |
| 横幅不再出现 | 可能已安装，也可能只是你以前点过关闭 | 先从浏览器菜单找安装入口；不要把“没再弹横幅”当成安装失败 |

关闭安装横幅后，当前实现会把这个选择记在本地存储里。以后想装，优先从浏览器菜单找安装入口，不要先清浏览器站点数据。

### 安装后的确认顺序

安装完成后，不要立刻删缓存、退登录或切设备。更稳妥的顺序是：

1. 从桌面或主屏图标打开一次新窗口。
2. 确认还是你预期的账号和项目列表。
3. 看一眼是否仍有 `待同步`、离线提示或迁移横幅。
4. 重要项目先做一次 `导出`；如果项目依赖附件，再做一次 `导出 ZIP`。

### 更新时应该点哪个“刷新”

当前代码里有两类更新提示，处理方式不同：

| 提示 | 来源 | 你应该做什么 |
| --- | --- | --- |
| `🚀 发现新版本` + `立即刷新` | Service Worker 发现新版本可激活 | 直接点 `立即刷新`。当前实现会先尝试 `activateUpdate()`，再走强制清缓存刷新 |
| `版本已更新` + `立即刷新` | 动态加载的 chunk 命中 stale chunk，不再继续重试 | 直接点 `立即刷新`，不要反复重开同一个弹窗或页面片段 |
| 错误边界里的 `刷新页面` | 普通页面级 reload | 只在没有更具体的更新提示时使用；这是普通刷新，不等同于“版本已更新”里的那条强制刷新路径 |

实际更新检查不是只在启动时做一次。当前实现还会在定时轮询、页面重新可见、窗口重新聚焦、网络恢复时继续检查，所以你可能在长时间挂着的页面里收到更新提示。

## 离线、服务中断与待同步

离线提示来自 `OfflineBannerComponent`。它把“完全离线”和“网络在线但云端服务暂时不可用”都视为可继续本地工作的状态，但提示文案不同。

| 你看到的状态 | 当前含义 | 最稳妥的动作 |
| --- | --- | --- |
| `离线模式 · 数据已安全保存` | 当前离线或同步服务不可用，但本地仍在保存 | 可以继续小范围编辑；保留当前标签页，不要切到另一台设备改同一批任务 |
| `离线数据已保存` | 移动端的短版离线提示 | 含义同上，只是文案更短 |
| `N 待同步` | 有 N 个本地操作还没同步到云端 | 先等它变化，不要为了“快一点”重复提交同一修改 |
| `网络已恢复` / `服务已恢复` | 连接或服务恢复，系统会自动尝试同步 | 等待待同步数量回落，再去另一台设备核对结果 |

一个容易混淆的点：当前实现里的“离线”不等于“异常”。它故意用的是安抚式提示，不是红色致命告警。真正要提高警惕的是下一节的 `存储空间不足`、`同步队列已冻结` 或 `存储失败`。

### 离线时的操作顺序

1. 继续在当前设备上做必要修改。
2. 不要同时在另一台设备编辑同一项目或同一任务。
3. 不要用“刷新页面试试看”来处理普通离线。
4. 网络恢复后，先等 `待同步` 变化，再检查关键任务是否还在。
5. 需要切账号、换设备、做大批量改动前，先做一次导出。

## 存储压力、队列冻结与逃生备份

这一部分要分三层看，不能把所有“存储问题”都当成一回事。

### 第一层：配额接近上限

`StorageQuotaService` 会在启动时检查一次，之后每 5 分钟再查一次。当前阈值是：

- `localStorage`：约 4 MB 进入 warning，约 4.5 MB 进入 critical；
- `IndexedDB`：约 40 MB 进入 warning，约 45 MB 进入 critical。

对应提示：

| 提示 | 当前含义 | 建议动作 |
| --- | --- | --- |
| `存储空间不足` | 达到 warning 阈值 | 先导出 JSON；如果项目依赖附件，再导出 ZIP；暂停大导入和大批量编辑 |
| `存储空间即将耗尽` | 达到 critical 阈值 | 立即导出；不要继续堆积待同步操作；处理浏览器空间问题后再继续 |

当前实现的自动“紧急清理”只会清理被标记为缓存类的本地项目，例如 flowchart cache、temp、debug 类键，不会把认证、偏好、主题或 undo session 当作“安全可删”的普通缓存。

### 第二层：同步队列被冻结

当 Action Queue 自己写 `localStorage` 命中 `QuotaExceededError` 时，当前实现会：

1. 先冻结同步队列写入；
2. 尝试把当前待同步队列备份到 IndexedDB；
3. 成功时提示 `同步队列已冻结。请释放浏览器存储后继续写入。`

这时页面上的离线指示会切到 `存储受限`。

这不是“数据已经丢了”，而是“系统在阻止继续把风险扩大”。推荐顺序：

1. 先停下新编辑，尤其是大文本、附件上传、批量操作。
2. 立即做常规项目导出；如果你看到专门的待同步导出入口，也把它导出来。
3. 保持当前标签页打开，先处理浏览器空间问题。
4. 当前实现会从 30 秒开始重试落盘，失败时指数退避，最长 5 分钟，最多 10 次；成功后会自动解冻并提示 `存储恢复`。

队列冻结专用的逃生导出文件名是：

- `nanoflow-pending-sync-<timestamp>.json`

它保存的是待同步操作、死信队列、冻结状态和冻结原因，不等同于正常的项目备份 JSON。

### 第三层：存储失败逃生模式

如果 `localStorage` 和 IndexedDB 都不可用，或者本地队列快照损坏且备份也恢复不了，当前实现会进入更高一级的逃生模式：

- 常驻错误提示：`🚨 存储失败 - 数据可能丢失`
- 文案要求：`请立即复制下方数据进行备份！`
- Shell 会打开 `StorageEscapeModal`

这个模态框里当前明确包含：

- 待同步队列 `queue`
- 死信队列 `deadLetter`
- 当前项目快照 `projects`
- 时间戳 `timestamp`

你可以做两件事：

1. 复制整段 JSON
2. 下载原始文件

模态框下载出来的文件名是：

- `nanoflow-backup-<timestamp>.json`

进入这一步后，最安全的动作顺序是：

1. 先复制 JSON。
2. 再下载文件。
3. 记下当时的项目、时间、待同步数量、死信数量。
4. 在确认备份文件已经保存前，不要关闭标签页、清站点数据或重新登录。

## 迁移期只读与仅导出

迁移横幅来自 `MigrationRecoveryComponent`，真正的保护规则来自 `WriteGuardService`。

### 两种模式的区别

| 横幅 | 当前语义 | 你应该怎么做 |
| --- | --- | --- |
| `当前为只读模式` | 当前地址禁止云端写入，但仍可浏览历史数据 | 停止把这个地址当作正常工作入口；先导出，再刷新或切回可写地址 |
| `此地址已停止接受新数据` | 进入 `export-only`，保护比只读更严格；代码注释明确写到连本地 IndexedDB 写都要禁止 | 立即导出本地数据，切换到新地址，再继续编辑 |

`export-only` 比 `read-only` 更严格。它不是“先离线存着，晚点再传”，而是“旧地址已经不该再产生新的可信写入”。

### 迁移横幅上的两个按钮怎么用

如果环境里配置了 `canonicalOrigin`，横幅会提供 `迁移到新地址`。当前实现会保留你当前的路径、查询参数和 hash，一并跳到新 origin。

`仅导出` 模式下还会出现 `导出本地数据`。当前源码里，这个按钮明确做的事情是发出 `nanoflow:request-data-export` 自定义事件。因此对用户来说，最稳妥的顺序是：

1. 先点横幅上的 `导出本地数据`。
2. 如果没有立即出现导出界面或下载，再走设置里的常规导出：
   - `导出`：项目 JSON 备份
   - `导出 ZIP`：附件备份
3. 只有在备份完成后，再点 `迁移到新地址`。

### 迁移时的操作顺序

1. 不要在旧地址继续新建、编辑、删除任务。
2. 先保住数据：JSON 导出，必要时再导出 ZIP。
3. 再切换到新地址。
4. 在新地址确认账号、项目列表和关键任务都对，再恢复工作。
5. 横幅右上角的关闭按钮只会在当前会话里隐藏提示，不代表迁移完成。

## 错误恢复弹窗和错误边界怎么选

### 可恢复错误弹窗

`ErrorRecoveryModalComponent` 当前支持这些固定行为：

- 显示标题、消息；
- 可选显示 `查看详细信息`；
- 显示一组由调用方传入的选项按钮；
- 可选显示 `记住此选择`；
- 可选显示倒计时自动选择；
- 倒计时结束时会选 `defaultOptionId`，如果没指定，就选第一项。

源码注释和 `GlobalErrorHandler.showRecoveryDialog()` 给出的典型选项包括：

- `重试 / 离线模式 / 丢弃更改`
- `使用本地修改 / 采用云端版本 / 合并并保留两边修改`

这些按钮不是每次都会一起出现，实际组合取决于触发错误的那条业务链路。推荐按下面的决策顺序处理：

| 选项 | 什么时候选 | 不该怎么用 |
| --- | --- | --- |
| `重试` | 网络短抖动、组件刚加载失败、你还没有做其他补救动作 | 连续无脑点很多次 |
| `离线模式` | 你需要先在本机保住改动，稍后再同步 | 以为它等同于“问题已经解决” |
| `使用本地修改` | 你已经确认本机副本才是权威版本，并且最好已做导出 | 还没备份、也没核对远端时就直接覆盖 |
| `采用云端版本` | 远端才是权威，且你接受本机当前修改被放弃 | 不看提示就直接选 |
| `合并并保留两边修改` | 双方修改都重要，你愿意接受合并后的人工复核 | 把它当成“永远不会出错”的自动修复 |
| `丢弃更改` / `danger` 风格按钮 | 你已经保住了备份，并明确决定放弃当前本地改动 | 把它当作普通关闭按钮 |

只要弹窗里带倒计时，就要先看默认选项是什么。涉及覆盖、放弃、迁移的场景，不要让默认选项替你做决定。

当前 coordinator 还支持“关闭弹窗而不选择任何恢复动作”。这条路径会走 `dismiss`，所以如果问题和数据保留有关，不要把“点掉弹窗”当作已经处理完成。

### 错误边界

`ErrorBoundaryComponent` 是另一条恢复路径，和上面的“选项型弹窗”不同：

- `重试`：重新执行调用方传进来的重试回调；
- `刷新页面`：普通 `window.location.reload()`；
- `返回首页`：跳到 `/`；
- `技术详情`：只在启用 `showDetails` 时显示。

如果你同时看到了“版本已更新 / 立即刷新”和错误边界，优先用更新提示里的那条刷新路径；它比普通 reload 更适合处理 stale chunk 或 SW 版本切换。

## 致命错误页和 404 页面

这两类页面都说明当前路由没有正常进入工作区，但它们的含义不同。它们不是同步冲突、回收站或项目删除的直接证据。

### 看见“应用出错了”

`/error` 是应用发生无法恢复错误时使用的致命错误页。页面可能显示错误发生时间、消息和可展开的技术详情，并提供两个可见动作：

| 动作 | 当前会做什么 | 什么时候优先使用 | 不要把它理解成 |
| --- | --- | --- |
| `简单刷新` | 清除当前会话的致命错误标记，然后从应用根地址重新进入 | 第一次遇到错误、你还需要先确认页面是否只是临时加载失败 | 已经清理了旧版本资源、同步队列或本地数据库 |
| `清除缓存并刷新` | 尝试清理应用缓存、注销 Service Worker、清理恢复标记，再重新导航；失败时走刷新兜底 | 已确认是 stale 资源、版本切换或缓存问题，且已保全当前重要数据 | “安全地重置所有问题”或替代 JSON/附件备份 |

“清除缓存并刷新”主要处理 Cache Storage、Service Worker 与恢复状态；它不应被当成清除或修复本地工作区的通用按钮。只要当前设备可能还有未同步的任务、附件或迁移中的本地数据，先尝试 `简单刷新`，记录错误详情，并在能够打开工作区后立即导出。无法确认本地数据是否安全时，不要把清缓存当作第一步。

若同一错误反复出现，记录错误详情、时间、当前 URL、账号和是否刚发生版本更新，再按 [安全升级与求助信息](#安全升级与求助信息) 的清单提供证据。不要为“恢复正常”而切换账号、清站点数据或在另一台设备重建同名任务。

### 看见“页面未找到”

`/not-found` 用于不匹配当前应用路由的 URL。页面提供“返回上一页”和“前往首页（`/projects`）”两个入口。它说明当前链接不存在或已经移动，不说明项目、任务或附件已经被删除。

遇到 404 时先回到上一页或首页，确认当前账号和项目列表，再从应用内导航重新打开目标。如果旧书签、Android 跳转或外部链接持续进入 404，保留原始链接和发生时间给维护者；不要通过清缓存、重装 PWA 或手工新建同名项目来处理路径错误。

## 本地数据库异常时怎么保全数据

启动期真正会被懒加载初始化的是 `StorageQuotaService` 和 `IndexedDBHealthService`。后者会：

- 启动时做一次健康检查；
- 之后每 30 分钟再做一次；
- 检查数据库能否打开、ObjectStore 是否齐全；
- 对 task/project/connection 各抽样最多 10 条记录，检查 JSON 解析和必填字段。

所以你应该把它理解为“启动期和运行期的轻量体检”，而不是“百分之百完整的全库修复”。

### 你可能看到的两类提示

| 提示 | 当前含义 | 最稳妥的动作 |
| --- | --- | --- |
| `数据库异常` | 存在 critical 级问题，例如数据库打不开、ObjectStore 缺失 | 立即导出；优先考虑从云端恢复；停止继续大量编辑 |
| `数据完整性警告` | 存在 error 级问题，例如部分记录异常、事务中止 | 先导出，再检查受影响项目；不要立刻清站点数据 |

当前实现对这些问题的建议文案是“从云端恢复数据或导出备份”。因此实操顺序应当是：

1. 先导出项目 JSON；
2. 如果项目有附件，再导出 ZIP；
3. 记录提示标题、时间、项目名；
4. 再决定是等待进一步恢复，还是切到云端作为权威来源。

## 安全升级与求助信息

需要向维护者反馈时，最有用的信息不是“坏了”，而是下面这些可复现线索：

1. 你看到的原始提示词：
   - `🚀 发现新版本`
   - `版本已更新`
   - `离线模式 · 数据已安全保存`
   - `存储空间不足`
   - `同步队列已冻结`
   - `🚨 存储失败 - 数据可能丢失`
   - `数据库异常`
   - `当前为只读模式`
   - `此地址已停止接受新数据`
2. 当时是浏览器标签页还是已安装的独立窗口。
3. 当时的 origin、项目名、当前账号和大致时间。
4. 你是否已经拿到了这些备份文件：
   - 正常项目导出 JSON
   - 附件 ZIP
   - `nanoflow-pending-sync-*.json`
   - `nanoflow-backup-*.json`
5. 你点过哪些按钮，以及结果有没有变化：
   - `立即刷新`
   - `重试`
   - `导出本地数据`
   - `迁移到新地址`

在完成备份前，不要先做这些高风险动作：

- 清除站点数据
- 卸载 PWA
- 切换到别的账号继续写
- 用旧备份覆盖当前状态
- 在第二台设备上继续编辑同一项目

## 常见问题

### 关闭安装提示后，怎样重新安装？

优先从浏览器菜单或地址栏找安装入口。当前实现会把“关闭安装提示”记在本地存储里，所以“横幅没再出现”不等于不能安装。不要先清站点数据。

### 看见 `导出本地数据`，是不是一定会立刻下载？

不应该直接假定。当前源码里，这个按钮明确会发出导出请求；如果没有立即出现导出界面或下载，直接改走设置里的 `导出` 和 `导出 ZIP`。

### `存储受限` 和 `存储失败` 有什么区别？

`存储受限` 说明系统还在尽量保护数据，但同步队列已经冻结，等待你释放空间后重试落盘。`存储失败` 说明本地主要存储路径已经不可用，应该立刻复制或下载逃生 JSON。

### 只读模式下还能继续写吗？

不要把它当成普通离线。`read-only` 代表云端写入已经被挡住；`export-only` 更严格，连本地持久化写入也不该再继续依赖。先导出，再切换到可写地址。

### `数据库异常` 出现后，第一步该做什么？

先导出，不要先清缓存。当前健康检查只说明“本地数据库存在严重问题”，不保证你清掉数据后还拿得回本机尚未同步的内容。
