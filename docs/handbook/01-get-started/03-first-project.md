# 第一个项目演练

这篇文档用一个小项目带你走完 NanoFlow 的核心日常流程：创建项目、建立任务树、编辑任务、暂存任务、进入 Focus、记录 Black Box、删除并恢复任务。请不要跳过恢复演练，因为它能帮你在真正误删前知道该去哪里找。

## 准备一个小项目主题

第一次不要导入旧系统里的全部任务。请选择一个小而真实的主题，例如：

- `整理个人文档`
- `准备下周复盘`
- `修一处家里设备问题`
- `规划一次短途出行`

好主题的特点是：

1. 你真的会推进它。
2. 它能拆成 3 到 8 个任务。
3. 即使误删，也不会造成严重损失。
4. 它能让你试到文本视图、停泊、Focus 和恢复。

## 创建项目和第一层任务

1. 打开 NanoFlow。
2. 创建一个项目，名称用结果描述，不要写成“杂项”。
3. 在文本视图里创建一个总任务，写清楚这个项目最终要达成什么。
4. 在总任务下面创建 3 个子任务：
   - 一个今天可以马上做的任务；
   - 一个需要等资料或别人回复的任务；
   - 一个只是想到但暂时不确定的任务。
5. 调整一次顺序，确认拖拽或排序后界面仍然符合预期。

示例结构：

```text
整理个人文档
  - 收集散落的文件夹
  - 删除重复压缩包
  - 把长期保留的资料放进思源
  - 给 NanoFlow 任务补充执行链接
```

## 补充任务细节

选择其中一个任务，补充正文。建议正文只写执行信息，不要塞入长篇资料。

可以写：

```markdown
- [ ] 找到桌面和下载目录里的文档
- [ ] 按年份初步分组
- [ ] 不确定的文件先放到“待判断”

参考位置：D:\Documents\Inbox
```

注意：

- 任务标题用于快速扫描。
- 任务正文用于说明怎么执行。
- 长篇背景资料更适合放在思源或外部文档里，再用链接或知识锚点连接。
- 路径里有空格时，优先用显式 Markdown 链接，减少识别歧义。

## 把暂时不做的任务放入 Parking Dock

选择那个“需要等资料或别人回复”的任务，把它放入 Parking Dock。

这样做的意义是：

- 它不会继续占用当前任务列表的注意力。
- 它也不会像归档一样被长期放到一边。
- 你以后可以从停泊坞里重新拉回它。
- 如果支持提醒或备注，可以写清楚“等谁、等什么、什么时候再看”。

不要把“今天不做”直接等同于“删除”或“归档”。停泊坞就是给这种中间状态准备的。

## 用 Focus 收窄今天要做的事

打开 Focus，按下面顺序试一次：

1. 如果 Gate 里有 Black Box 项目，先处理它。
2. 选择今天真正要推进的 1 到 3 个任务。
3. 不要把整个项目都塞进 Focus。
4. 完成一个任务后，回到文本视图确认任务状态是否符合预期。
5. 如果一个任务暂时不能做，考虑停泊，而不是留在专注队列里占位置。

Focus 的目的不是创建第二套任务系统，而是把当前时段的注意力缩小。

## 演练删除和恢复

请专门创建一个无关紧要的测试任务，然后：

1. 删除这个测试任务。
2. 打开回收、恢复或归档恢复入口。
3. 找到刚刚删除的任务。
4. 执行恢复。
5. 回到原项目确认它回来了。

做这个演练有两个好处：

- 你知道误删后第一时间去哪里找。
- 你能确认当前浏览器和本地持久化路径工作正常。

如果你找不到恢复入口，不要继续做大规模删除，先去读 [备份与恢复](../03-data-sync-safety/03-backup-and-restore.md)。
