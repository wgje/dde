## 准备一个小项目主题

第一次不要导入旧系统里的全部任务。请选择一个小而真实的主题，例如：

- `整理个人文档`
- `准备下周复盘`
- `修一处家里设备问题`
- `规划一次短途出行`

好主题的特点是：

1. 你真的会推进它。
2. 它能拆成 3 到 8 个任务。
3. 即使误删，也不会造成严重损失。
4. 它能让你试到文本视图、停泊、Focus 和恢复。

## 开始前的安全边界

这次演练的目标不是把所有真实资料迁进来，而是证明当前浏览器里的基本工作流可用。开始前准备好下面三件事：

| 准备 | 为什么 | 完成标准 |
| --- | --- | --- |
| 一个不会造成损失的项目主题 | 允许你安全练习删除和恢复 | 即使整个项目被删除，你也不需要从外部重建重要资料 |
| 一个可复制的短文本 | 用来验证标题、正文和保存 | 不使用密码、证件、客户资料或私密附件 |
| 一个备份位置 | 后续能验证你知道导出文件在哪里 | 知道下载文件夹或本地备份目录，而不是只看浏览器下载提示 |

如果你正在使用本地模式，先确认你理解当前数据只在这个浏览器范围内；如果已经登录并准备跨设备，先读 [离线优先模型](../03-data-sync-safety/01-offline-first-model.md)。这一步不要求你马上配置 Supabase，但要求你不要把这次小演练误当成云端恢复已经验证完成。

## 创建项目和第一层任务

1. 打开 NanoFlow。
2. 创建一个项目，名称用结果描述，不要写成“杂项”。
3. 在文本视图里创建一个总任务，写清楚这个项目最终要达成什么。
4. 在总任务下面创建 3 个子任务：
   - 一个今天可以马上做的任务；
   - 一个需要等资料或别人回复的任务；
   - 一个只是想到但暂时不确定的任务。
5. 调整一次顺序，确认拖拽或排序后界面仍然符合预期。

创建时用“结果 + 动作”命名，而不是“杂项”“看看”“处理一下”。例如：`整理个人文档` 比 `文件` 更容易在搜索、停车坞和恢复时判断含义。

示例结构：

```text
整理个人文档
  - 收集散落的文件夹
  - 删除重复压缩包
  - 把长期保留的资料放进思源
  - 给 NanoFlow 任务补充执行链接
```

第一层任务创建后，先做一次短检查：标题是否能一眼看出动作、子任务是否真的属于同一结果、等待中的事是否没有伪装成今天能直接完成的任务。层级用于表达分解关系，不用于堆放所有想到的内容；一时还不确定的想法可以先放进 Black Box。

## 补充任务细节和下一步

选择其中一个任务，补充正文。建议正文只写执行信息，不要塞入长篇资料。

可以写：

```markdown
- [ ] 找到桌面和下载目录里的文档
- [ ] 按年份初步分组
- [ ] 不确定的文件先放到“待判断”

参考位置：D:\Documents\Inbox
```

注意：

- 任务标题用于快速扫描。
- 任务正文用于说明怎么执行。
- 长篇背景资料更适合放在思源或外部文档里，再用链接或知识锚点连接。
- 路径里有空格时，优先用显式 Markdown 链接，减少识别歧义。

再给其中一个任务补一条“回来后第一步”。这条内容可以写在正文或注意事项里，例如：`下次先核对下载目录的日期范围，再开始移动文件`。它不是一个新的子任务，而是防止你被打断后重新理解上下文的短提示。

如果任务已经能估时、需要等待或需要高强度思考，可以补充计划字段和注意事项；这些字段用于扫读和安排，不应代替正文里的实际步骤。详细写法见 [任务僚机与计划信息](../02-use-nanoflow/08-task-sidecar-and-planning.md)。

## 做一次本地保存检查

不要只看编辑器里有文字就进入下一步。用一个无风险项目验证当前本地持久化：

1. 修改一个测试任务的标题和正文。
2. 等待界面结束当前保存状态，不要连续重复点同一动作。
3. 刷新同一个浏览器页面。
4. 确认项目、任务标题、正文和刚调整的顺序还在。
5. 如果你已登录且准备跨设备，等同步状态没有待处理提示后，再在另一台设备打开同一项目核对一条任务。

这只证明当前路径可用，不是备份。刷新后仍在说明本地持久化接住了数据；跨设备看得到才说明云端路径也已经跑通。任何一项不符合预期时，先停止把更多真实数据放进来，转到 [离线优先模型](../03-data-sync-safety/01-offline-first-model.md) 或 [应用安装、离线与错误恢复](06-pwa-offline-and-error-recovery.md) 排查。

## 把暂时不做的任务放入 Parking Dock

选择那个“需要等资料或别人回复”的任务，把它放入 Parking Dock。

这样做的意义是：

- 它不会继续占用当前任务列表的注意力。
- 它也不会像归档一样被长期放到一边。
- 你以后可以从停泊坞里重新拉回它。
- 如果支持提醒或备注，可以写清楚“等谁、等什么、什么时候再看”。

不要把“今天不做”直接等同于“删除”或“归档”。停泊坞就是给这种中间状态准备的。

放入 Dock 前，给任务写清楚三个问题：在等什么、下次什么时候看、回来后先做什么。这样恢复时不需要凭记忆猜测。把它重新打开、完成或再次停泊时，仍以 [Parking Dock 停泊坞](../02-use-nanoflow/03-parking-dock.md) 的状态流程为准。

## 用 Focus 审查输入，而不是另建一份任务清单

打开 Focus，按下面顺序试一次：

1. 如果 Gate 里有 Black Box 项目，先处理它。
2. 看清每一张 Gate 卡是“已读”“完成”还是需要先补充信息；不要连续快速点击还在处理中的卡片。
3. Gate 清完后，回到文本视图或 Flow 视图，从你已经建立的任务树中决定当前要推进的任务。
4. 完成一个任务后，回到原任务视图确认任务状态是否符合预期。
5. 如果一个任务暂时不能做，考虑停泊；如果只是突然想到的内容，放入 Black Box，避免为了记录而重排整个任务树。

当前实现里，Focus 自动维护的是 Gate 对 Black Box 待处理项的审查队列和 Strata 历史层，不是把项目任务复制成一份独立的“今日任务队列”。Focus 的目的仍是收窄注意力，但任务的真实结构、状态和层级继续由文本视图、流程图和停泊坞管理。详细边界见 [Focus 专注模式](../02-use-nanoflow/04-focus-mode.md)。

## 演练删除和恢复

请专门创建一个无关紧要的测试任务，然后：

1. 删除这个测试任务。
2. 打开回收、恢复或归档恢复入口。
3. 找到刚刚删除的任务。
4. 执行恢复。
5. 回到原项目确认它回来了。

做这个演练有两个好处：

- 你知道误删后第一时间去哪里找。
- 你能确认当前浏览器和本地持久化路径工作正常。

如果你找不到恢复入口，不要继续做大规模删除，先读 [项目、设置与回收站](../02-use-nanoflow/09-project-settings-and-recovery.md)，再按 [备份与恢复](../03-data-sync-safety/03-backup-and-restore.md) 的顺序处理。

删除演练完成后，再补一次导出练习：导出当前小项目的 JSON，并确认文件确实在你选择的位置。项目里有附件时，结构 JSON 不等于附件文件；需要完整迁移或恢复时还要按备份页保留附件 ZIP。

## 完成演练后如何开始真实项目

当下面的检查都通过，再把真实工作放进 NanoFlow：

| 检查 | 你应该已经验证 |
| --- | --- |
| 创建与编辑 | 项目、任务树和正文可以在当前浏览器保存下来 |
| 中断恢复 | 一个等待任务能停泊，并能知道如何再次找到它 |
| 快速记录 | 突然想到的内容可以放 Black Box，而不是打乱当前任务树 |
| 删除恢复 | 你知道从哪里找回一个无风险测试任务 |
| 数据保护 | 你已经做过一次 JSON 导出，并知道附件需要单独处理 |
| 跨设备（可选） | 已登录时，至少验证过一条任务在另一台设备刷新后可见 |

真实项目的第一周仍建议小步推进：每次只迁入一个主题，在大批量整理前做导出，并把同步异常先当作数据保护问题而不是“再点一次就好”的界面问题。
