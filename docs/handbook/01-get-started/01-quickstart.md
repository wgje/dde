# 快速开始

这篇文档只解决一件事：让你尽快把 NanoFlow 在本机打开，并确认“本地使用路径”是通的。这里不会一次性配置登录、云同步、附件、语音转写或 Android 小组件，那些属于后续步骤。

## 运行前准备

你需要准备：

| 项目 | 要求 | 为什么需要 |
| --- | --- | --- |
| Node.js | `>= 22.14.0` | 当前脚本、Angular 构建和测试工具按这个版本线维护 |
| npm | 使用仓库锁文件安装 | 保证依赖版本和项目当前状态一致 |
| 浏览器 | 推荐 Chrome 或 Chromium | PWA、桌面本地备份和部分文件能力在 Chromium 系浏览器上最完整 |
| 终端目录 | `D:\Code\dde` 或你的仓库根目录 | 后续命令都假设从仓库根目录执行 |

如果你只是想体验本地功能，不需要先准备 Supabase。没有 Supabase 时，NanoFlow 仍然可以创建项目、编辑任务、使用文本视图、Parking Dock、Focus、Black Box 文字记录、导出导入和本地备份。

## 安装依赖

在仓库根目录运行：

```bash
npm install
```

安装完成后，先不要急着导入真实数据。第一步只需要确认依赖安装没有报错。

如果安装失败，按这个顺序检查：

1. 确认 Node.js 版本满足 `>= 22.14.0`。
2. 确认当前目录是仓库根目录，能看到 `package.json`。
3. 确认网络能访问 npm registry。
4. 不要手动删除或重写 `package-lock.json`，除非你明确是在做依赖维护。

## 启动应用

运行：

```bash
npm start
```

这个命令会先执行环境准备，再通过项目脚本启动 Angular 开发服务器。默认优先使用 `3000` 端口；如果端口被占用，项目脚本可能选择下一个可用端口。终端输出里会显示实际访问地址。

如果你必须固定端口，可以设置：

```bash
PORT=3000
```

或使用项目支持的 `NANOFLOW_DEV_SERVER_PORT`。

## 打开后怎么验收

应用打开后，不要只看“页面有东西”就算成功。请按下面步骤验收：

1. 页面能进入主界面，没有一直停在白屏或加载中。
2. 能创建或看到一个项目入口。
3. 能创建一个测试任务。
4. 修改测试任务标题后，界面立即更新。
5. 刷新浏览器后，测试任务仍然存在。
6. 删除一个测试任务后，能从恢复或回收入口找回。
7. 打开 Focus 或 Parking Dock，确认主界面以外的核心功能能加载。

完成这些检查，才说明本地基础路径可用。

## 常见问题

| 问题 | 先检查什么 | 处理建议 |
| --- | --- | --- |
| `npm install` 失败 | Node 版本、网络、当前目录 | 先修环境，不要改业务代码 |
| `npm start` 后端口不是 3000 | 端口可能被占用 | 以终端实际输出的 URL 为准 |
| 页面打开但没有云同步 | 这是正常的 | 云同步需要额外 Supabase 配置 |
| 刷新后测试任务不见了 | 本地持久化可能没写入或浏览器隔离 | 换 Chromium 浏览器重试，并检查是否在隐身模式 |
| 想上传附件但失败 | Storage 还没配置 | 先读云同步和 Supabase 运维文档 |
