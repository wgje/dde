# 本地离线模式

本地离线模式不是“演示模式”。NanoFlow 的核心设计就是先把操作写到本地，让界面立即响应，再在有云服务时后台同步。你完全可以先不登录、不配置 Supabase，只用本地模式验证这个工作台是否适合自己。

## 本地离线模式是什么意思

本地离线模式下，NanoFlow 会优先把项目、任务和界面状态保存在当前浏览器环境里。你可以理解成：

- 数据先在本机浏览器里存在。
- 界面变化不需要等网络请求返回。
- 没有 Supabase 时，不会自动同步到其他设备。
- 清理浏览器数据可能会清掉本地项目。

因此，本地模式适合试用、单设备使用和离线编辑；但如果你要长期保存重要数据，必须配合导出、桌面备份或云同步。

本地模式不是临时预览，也不是只读体验。任务、项目、停车坞和专注流程都可以继续工作；区别在于这些数据使用本地身份隔离，不能把当前浏览器里的内容当成已登录账户或云端副本。

当私有实例尚未配置 Supabase 时，应用仍会保留本地优先的访问路径。这方便先验证工作流，但不代表实例后来会自动获得登录、云同步或跨设备附件能力。

## 什么时候应选择本地模式

先按你的工作目标选择，不要因为页面能打开就假定数据已经安全保存到云端：

| 你的情况 | 更合适的方式 | 为什么 |
| --- | --- | --- |
| 第一次试用、临时整理、只有一台可信设备 | 本地模式 | 可以立即开始，不必先配置云服务 |
| 飞行、弱网、现场记录 | 本地模式或已登录账户的离线工作 | 当前操作先保留在本机；网络恢复后再确认同步状态 |
| 长期保存重要项目 | 本地模式加规律导出/本地备份，或尽早启用云同步 | 浏览器存储不是备份策略 |
| 两台以上设备轮换编辑 | 登录并完成云同步配置 | 本地模式不会把一台设备的数据自动带到另一台设备 |
| 团队共享、合规留存、部署自己的服务 | 私有部署和云端账号 | 本地浏览器数据不提供账户级权限、审计或共享边界 |

如果你暂时无法决定，先以本地模式建立一个小项目，验证刷新后仍可看到内容，再建立导出习惯。真正开始处理不可替代资料之前，先完成 [备份与恢复](../03-data-sync-safety/03-backup-and-restore.md) 中的一次可用备份。

## 如何确认自己正在使用本地模式

本地模式的可见提示是顶部的 **Demo 模式** 横幅：它明确说明“数据仅保存在当前浏览器，清除缓存会丢失数据”，并提供“登录 / 注册”和私有部署入口。把它当作数据边界提示，而不是普通通知。

| 看到的情况 | 它表示什么 | 下一步 |
| --- | --- | --- |
| 顶部显示 Demo 模式横幅 | 当前操作仍处在本地浏览器的数据范围内 | 继续单设备使用前先安排导出或本地备份 |
| 横幅被关闭 | 仅隐藏提示，不会登录、同步、迁移或备份数据 | 仍按本地模式处理数据；需要云端时主动登录 |
| 点击“登录 / 注册” | 应用清除本地模式标记并重新加载，进入登录路径 | 登录前不要清理浏览器数据；登录后按迁移提示决定如何处理已有本地内容 |
| 私有实例没有配置云端 | 应用可以允许本地访问 | 把它视为本地使用环境；只有完成 [云同步配置](04-cloud-sync-setup.md) 后才讨论跨设备同步 |

提示横幅可以被关闭一段时间，所以“没有横幅”不等于数据已经上云。判断重要数据是否可跨设备使用时，查看登录和同步状态，而不是只凭横幅是否出现。

## 本地数据保存在哪里，以及不会保存到哪里

本地模式的数据属于**当前浏览器环境**。实际含义是：同一台电脑换浏览器、换浏览器配置文件、使用隐身窗口，或清理该站点的浏览器数据，都可能得到一个不同或空的工作区。

NanoFlow 会为本地模式使用独立的本地数据身份，避免把未登录时的内容当成某个云端账户的数据。你不需要维护这个技术标识；需要记住的是，它不会自动变成你之后登录的账户，也不会天然出现在另一台设备上。

本地模式不会替你完成以下事情：

- 不会把项目、任务或 Black Box 自动上传到 Supabase。
- 不会为你建立第二台电脑、手机或 Android 小组件可读取的云端副本。
- 不会把浏览器缓存当成可恢复的历史版本。
- 不会在你关闭 Demo 提示后自动切换为登录账户。

浏览器可能会把站点数据拆分到不同存储区域。不要手动编辑、复制或删除单个浏览器键值来“迁移”项目；这样无法证明任务、附件、停泊状态和离线队列仍然一致。需要迁移时使用应用提供的导出、导入、备份或登录后迁移流程。

## 本地可用的功能

| 功能 | 本地模式下能做什么 | 使用建议 |
| --- | --- | --- |
| 文本任务树 | 创建、编辑、排序、搜索、删除和恢复任务 | 日常主界面优先用它 |
| Markdown 内容 | 给任务写说明、清单、链接和备注 | 长文资料建议放思源，任务里写执行信息 |
| 流程图视图 | 打开图形视图、查看关系、导出图或结构 | 手机端按需打开，不要当常驻界面 |
| Parking Dock | 暂存暂时不做但不想忘的任务 | 不要用归档代替停泊 |
| Focus Mode | 使用 Gate、专注队列、Strata 等本地工作流 | 适合开始工作前收窄范围 |
| Black Box 文字记录 | 快速记录想法，后续通过 Gate 处理 | 文字可本地用，语音转写要云端 |
| 回收与归档恢复 | 找回普通删除或归档的内容 | 高风险清理前仍要先备份 |
| JSON 导出/导入 | 迁移或恢复结构数据 | 附件文件需要单独 ZIP |
| 桌面本地备份 | 支持时可定期写入本地备份目录 | 推荐选择网盘同步目录 |

即使某项功能在本地可打开，也不要把“可以使用”理解为“可以跨设备恢复”。例如本地文本记录和任务状态可以继续维护，但在另一台设备继续之前，仍需要完成导出/导入或云端同步。

## 必须配置云端后才完整的功能

| 功能 | 需要什么 |
| --- | --- |
| 登录账户 | Supabase Auth |
| 多设备同步 | Supabase 数据库、RLS、同步配置 |
| 附件上传与跨设备访问 | 私有 Storage bucket `attachments` |
| 语音转写 | `transcribe` Edge Function 和 Groq Secret |
| Android 小组件摘要 | widget 相关 Edge Functions |
| FCM dirty push 刷新 | Android 配置、FCM Secrets、`widget-notify` |
| 服务端病毒扫描 | 对应 Edge Function 或扫描路径 |

如果你没有这些配置，本地任务仍然可用，但对应云端能力不会完整工作。

## 本地模式的数据风险

使用本地模式时，最常见的数据风险来自下面几类操作：

1. **清理浏览器数据**：可能删除 IndexedDB、LocalStorage 或缓存。
2. **换浏览器**：Chrome 里的数据不会自动出现在 Edge 或 Firefox。
3. **隐身模式**：退出后本地数据可能被清掉。
4. **系统清理工具**：某些清理工具会删除浏览器站点数据。
5. **误以为已经云同步**：没有登录和 Supabase 时，本地变化不会自动到其他设备。

还有两种容易被忽略的风险：

6. **先登录或清理再决定迁移**：登录后的本地数据迁移可能需要你选择可信来源；在看清选项前清空浏览器数据，会让可比较的本地副本消失。
7. **本地和另一台设备同时继续改同一项目**：两个本地工作区彼此不知道对方的变更。之后再导入或接入云端时，无法把它们当作天然连续的历史。

遇到存储空间提示、迁移保护、可恢复错误或页面提示不能继续写入时，先停止会扩大差异的操作，按 [PWA、离线与错误恢复](06-pwa-offline-and-error-recovery.md) 保存现有数据。不要反复刷新、清缓存或新建同名任务来“试试能不能恢复”。

## 安全使用方法

建议你这样使用本地模式：

1. 第一次正式使用前，先创建测试项目并确认刷新后仍存在。
2. 每次大规模整理前，先导出 JSON。
3. 有附件时，结构数据和附件 ZIP 要分开导出。
4. 如果浏览器支持桌面本地备份，把备份目录放到可信网盘同步目录里。
5. 在没有备份前，不要清理站点数据、卸载浏览器或更换用户资料。
6. 如果以后要开启云同步，先读同步冲突文档，避免多设备同时编辑同一批任务。

为了让这些动作真正可恢复，建议把日常工作拆成两个节奏：

| 时机 | 要做的事 | 完成标准 |
| --- | --- | --- |
| 第一次正式使用 | 建一个测试项目，创建并编辑一条任务，然后刷新页面 | 仍能在同一浏览器看到相同项目和任务 |
| 每次大规模整理前 | 导出 JSON；有附件时另存附件 ZIP | 导出的文件能在你选择的安全位置找到，不只停留在下载栏 |
| 每周或每个重要里程碑 | 运行一次本地备份或做一份导出副本 | 副本不与唯一原始数据放在同一个易清理位置 |
| 准备换浏览器、重装系统或清理空间前 | 完成导出，并确认恢复路径 | 知道要导入哪个 JSON、附件 ZIP 放在哪里、是否还要保留旧浏览器 |

“刷新后还在”只能证明当前浏览器暂时保留了数据，不能代替导出或备份。对于不可重建的工作，至少保留一个离开浏览器存储的副本。

## 从本地模式转到登录和云同步

转到云端前，先把目标说清楚：你是要保留本地工作区、用云端数据替换它，还是先查看两边再决定。不要把“登录成功”当成数据迁移已经完成。

推荐顺序：

1. 在当前本地浏览器完成一次导出；如果项目有附件，同时保留附件 ZIP 或本地备份。
2. 停止在其他浏览器或设备继续编辑同一批任务，避免同时产生两份本地历史。
3. 通过顶部提示或登录入口进入账户登录。登录动作会退出本地模式并重新加载应用。
4. 如果应用发现已有本地访客数据并显示迁移选择，不要凭名称猜测结果。先阅读每个策略对应的可信数据来源、完整性检查和失败恢复说明。
5. 按 [项目设置、迁移与恢复](../02-use-nanoflow/09-project-settings-and-recovery.md) 完成迁移或保留本地副本的选择。
6. 登录后先验证一个小项目、一个任务和同步状态，再在另一台设备继续工作。

如果你只想部署自己的私有实例，不想立即迁移已有本地数据，也先完成第 1 步。部署、Supabase 配置和账户边界见 [私有部署](../04-deploy-operate/01-private-deployment.md)。

## 数据看起来不对时的恢复顺序

下面的顺序优先保护现有证据。任何一步如果你准备清理浏览器数据、切换账户或覆盖项目，都先完成导出。

### 刷新后看不到项目或任务

1. 停止在空白工作区继续创建任务，避免把“恢复前”和“恢复后”的内容混在一起。
2. 确认是否仍使用原来的浏览器、原来的浏览器配置文件和同一个站点地址；不要在隐身窗口里判断原数据是否丢失。
3. 查看是否已登录到另一个账户，或刚刚从本地模式切换到了登录路径。
4. 如果页面出现存储、迁移或错误恢复提示，先按 [PWA、离线与错误恢复](06-pwa-offline-and-error-recovery.md) 的保护步骤处理。
5. 查找最近一次 JSON 导出、本地备份或附件 ZIP，并通过 [备份与恢复](../03-data-sync-safety/03-backup-and-restore.md) 选择恢复方式。

没有导出、备份或仍在原浏览器中的站点数据时，不能承诺恢复已经被浏览器清除的内容。此时不要使用不明的浏览器恢复工具覆盖当前配置文件；先保留现有状态，并把问题与已采取操作记录下来。

### 本地内容和云端内容看起来不一致

1. 暂停两边继续编辑，记下项目、任务标题和最近一次修改的位置。
2. 确认你看到的是本地模式还是已登录账户；不要只以是否出现 Demo 横幅判断。
3. 在本地浏览器导出当前结构数据，保留可回退副本。
4. 再按 [同步与冲突处理](../03-data-sync-safety/02-sync-and-conflicts.md) 和迁移页面的策略判断可信来源。

## 常见问题

### 关闭 Demo 模式横幅后，我的数据是不是已经安全了？

不是。关闭动作只隐藏提示，不会登录、同步、备份或迁移数据。继续把它当作当前浏览器中的本地数据，直到你验证了登录和同步状态。

### 没配置 Supabase，为什么应用仍能打开和编辑？

应用为未配置云端的场景保留本地优先访问路径，所以你可以先使用工作台。它不表示账号、云端数据库、附件 Storage 或跨设备同步已经生效。

### 登录后，本地任务会自动变成云端任务吗？

不要做这个假设。登录会退出本地模式并重新加载；如果出现本地访客数据迁移流程，请按界面和 [项目设置、迁移与恢复](../02-use-nanoflow/09-project-settings-and-recovery.md) 的说明选择。登录前先导出当前本地副本。

### 我能否在两台设备各自用本地模式，再晚点合并？

不建议把它当成协作方式。两台设备的本地历史彼此独立，后续合并时需要人工判断。需要轮换设备时，使用云同步，或在每次切换前按明确的导出/导入流程操作。

### 清除了浏览器缓存后还能恢复吗？

只能从仍然存在的导出、附件 ZIP、本地备份或云端副本恢复。浏览器站点数据被清除后，本地模式本身不会提供另一份隐藏的云端副本。
