# 本地离线模式

本地离线模式不是“演示模式”。NanoFlow 的核心设计就是先把操作写到本地，让界面立即响应，再在有云服务时后台同步。你完全可以先不登录、不配置 Supabase，只用本地模式验证这个工作台是否适合自己。

## 本地离线模式是什么意思

本地离线模式下，NanoFlow 会优先把项目、任务和界面状态保存在当前浏览器环境里。你可以理解成：

- 数据先在本机浏览器里存在。
- 界面变化不需要等网络请求返回。
- 没有 Supabase 时，不会自动同步到其他设备。
- 清理浏览器数据可能会清掉本地项目。

因此，本地模式适合试用、单设备使用和离线编辑；但如果你要长期保存重要数据，必须配合导出、桌面备份或云同步。

## 本地可用的功能

| 功能 | 本地模式下能做什么 | 使用建议 |
| --- | --- | --- |
| 文本任务树 | 创建、编辑、排序、搜索、删除和恢复任务 | 日常主界面优先用它 |
| Markdown 内容 | 给任务写说明、清单、链接和备注 | 长文资料建议放思源，任务里写执行信息 |
| 流程图视图 | 打开图形视图、查看关系、导出图或结构 | 手机端按需打开，不要当常驻界面 |
| Parking Dock | 暂存暂时不做但不想忘的任务 | 不要用归档代替停泊 |
| Focus Mode | 使用 Gate、专注队列、Strata 等本地工作流 | 适合开始工作前收窄范围 |
| Black Box 文字记录 | 快速记录想法，后续通过 Gate 处理 | 文字可本地用，语音转写要云端 |
| 回收与归档恢复 | 找回普通删除或归档的内容 | 高风险清理前仍要先备份 |
| JSON 导出/导入 | 迁移或恢复结构数据 | 附件文件需要单独 ZIP |
| 桌面本地备份 | 支持时可定期写入本地备份目录 | 推荐选择网盘同步目录 |

## 必须配置云端后才完整的功能

| 功能 | 需要什么 |
| --- | --- |
| 登录账户 | Supabase Auth |
| 多设备同步 | Supabase 数据库、RLS、同步配置 |
| 附件上传与跨设备访问 | 私有 Storage bucket `attachments` |
| 语音转写 | `transcribe` Edge Function 和 Groq Secret |
| Android 小组件摘要 | widget 相关 Edge Functions |
| FCM dirty push 刷新 | Android 配置、FCM Secrets、`widget-notify` |
| 服务端病毒扫描 | 对应 Edge Function 或扫描路径 |

如果你没有这些配置，本地任务仍然可用，但对应云端能力不会完整工作。

## 本地模式的数据风险

使用本地模式时，最常见的数据风险来自下面几类操作：

1. **清理浏览器数据**：可能删除 IndexedDB、LocalStorage 或缓存。
2. **换浏览器**：Chrome 里的数据不会自动出现在 Edge 或 Firefox。
3. **隐身模式**：退出后本地数据可能被清掉。
4. **系统清理工具**：某些清理工具会删除浏览器站点数据。
5. **误以为已经云同步**：没有登录和 Supabase 时，本地变化不会自动到其他设备。

## 安全使用方法

建议你这样使用本地模式：

1. 第一次正式使用前，先创建测试项目并确认刷新后仍存在。
2. 每次大规模整理前，先导出 JSON。
3. 有附件时，结构数据和附件 ZIP 要分开导出。
4. 如果浏览器支持桌面本地备份，把备份目录放到可信网盘同步目录里。
5. 在没有备份前，不要清理站点数据、卸载浏览器或更换用户资料。
6. 如果以后要开启云同步，先读同步冲突文档，避免多设备同时编辑同一批任务。
