# 启动、登录与状态提示

NanoFlow 启动时会先恢复当前设备的本地状态，再根据你的登录状态决定是否继续同步云端数据。理解这段过程，可以避免把“正在初始化”“离线可用”“等待同步”和“登录失效”误认为同一种故障。

## 打开应用后会发生什么

正常启动时，NanoFlow 会按大致顺序完成这些动作：

1. 先加载当前浏览器保存的本地项目快照和界面状态。
2. 识别当前是否已有登录会话。
3. 如果是本地离线项目，直接让你进入可编辑状态。
4. 如果已经登录，恢复当前用户对应的项目状态，并在后台检查云端变更。
5. 需要时再懒加载较重的功能，例如 Flow、弹窗或 Android 小组件入口。

因此，刚打开时短暂看到“正在恢复”或“正在检查登录”并不代表数据丢失。重点是不要在初始化还没有完成时反复刷新、反复切换账号或立刻清理浏览器数据。

## 本地项目和云端项目的启动差别

| 项目类型 | 启动时优先读取什么 | 什么时候会访问云端 | 你需要注意什么 |
| --- | --- | --- | --- |
| 本地离线项目 | 当前浏览器里的本地快照 | 不需要云端即可编辑 | 换浏览器或清站点数据前先导出 |
| 已登录的云同步项目 | 本地快照和当前用户会话 | 后台拉取增量、处理待同步操作 | 等同步稳定后再换设备 |
| 刚登录的新设备 | 会话和可恢复项目元数据 | 需要云端加载项目 | 初次加载期间不要误判为空项目 |

本地优先并不等于云端永远不重要。它只是保证网络慢或暂时离线时，你仍能先进入可工作的状态。

## 登录、退出和切换账号

登录状态决定你能看到哪一组云端数据。操作时请遵循下面的规则：

1. 登录前，确认本地离线项目是否已经导出或确定要保留在当前设备。
2. 登录后，等待当前用户项目加载完成，再创建大量新内容。
3. 退出前，确认没有长期待同步的更改。
4. 切换账号后，不要把上一个账号的本地快照当成新账号的云端项目。
5. 如果应用提示会话恢复中，先等恢复完成，不要连续点击登录、退出和刷新。

如果你使用同一台设备登录不同账户，最安全的做法是先让前一个账户的同步稳定，再退出和切换。

退出过程中如果当前会话 identity 已改变，应用会停止旧会话的后续清理，避免迟到的登出操作清除新账号的数据。遇到这种情况，先确认页面显示的账号和项目，再决定是否重新退出。

## 注册、重置密码和本地模式

登录窗口除了登录外，还提供注册、重置密码和本地模式入口。它们的结果不同，不能把“暂时不登录”与“换了一个云端账号”混为一谈。

### 注册

注册时填写邮箱、密码和确认密码。界面会给出密码强度提示；至少使用 8 位密码，并尽量包含大小写字母、数字或其他字符。提交后等待当前请求结束，不要在加载中连续点击创建账户或反复按回车。

注册前先确认你想把哪一类数据放到该账户下：

- 已有本地离线项目时，先导出或确认其保留策略；
- 不要把不同人的项目放进同一个账户后再依赖任务标题区分；
- 注册成功后，先等待项目加载完成，再导入或批量创建大量任务；
- 公共设备上不要让浏览器记住密码，也不要把恢复链接和认证邮件转发到不可信渠道。

### 重置密码

选择“重置密码”后，输入要恢复的邮箱并发送请求。界面会显示已发送状态，但邮箱实际到达时间取决于认证服务和邮件系统。

安全顺序：

1. 确认邮箱拼写正确，再提交一次。
2. 等待请求完成，不要连续反复发送。
3. 在收件箱和垃圾邮件中查找重置邮件；不要公开转发重置链接。
4. 完成密码更新后，回到 NanoFlow 重新登录。
5. 如果当前设备有重要待同步内容，重新登录前先保留浏览器数据并确认本地项目仍在。

重置密码解决的是账号访问问题，不会自动修复同步冲突、恢复已清除的浏览器数据或改变本地离线项目的归属。

### 本地模式

选择本地模式后，你可以在不登录的情况下继续使用当前浏览器中的本地工作区。它适合试用、单设备临时工作或明确不需要云同步的场景。

本地模式的边界：

- 数据主要留在当前浏览器和当前设备；
- 不会自动同步到其他设备或其他账号；
- 清理站点数据、换浏览器或重装系统前必须导出；
- 附件、跨设备访问和云端能力需要各自的配置，不能因进入本地模式而自动可用。

完整边界见 [本地离线模式](02-local-only-mode.md)。不要为了跳过一次登录问题就切换本地模式并继续在另一台设备编辑同一项目；那会制造两个没有自动合并关系的数据来源。

## 怎样理解状态提示

常见状态可以这样理解：

| 提示或现象 | 通常意味着什么 | 优先动作 |
| --- | --- | --- |
| 正在初始化或恢复 | 正在读取本地状态、会话或项目元数据 | 等待完成，不要连续刷新 |
| 本地已保存 | 当前设备已经接受了你的操作 | 可以继续工作，但云端可能仍待同步 |
| 待同步或重试中 | 变更仍在等待网络或云端恢复 | 保留浏览器数据，检查网络和登录 |
| 离线 | 仍可编辑本地内容 | 不要期待另一台设备立刻看到更新 |
| 登录失效 | 当前会话不能访问云端数据 | 重新登录，避免清本地数据 |
| 项目暂时为空 | 可能是加载尚未完成，也可能是账户/权限不对 | 先检查登录账户和网络 |

状态提示告诉你“当前在哪个阶段”，不是让你立即做破坏性修复。优先等待、确认账户、导出，再进行下一步。

如果你需要安装 PWA、判断“存储受限”或使用错误恢复弹窗，继续读 [应用安装、离线与错误恢复](06-pwa-offline-and-error-recovery.md)。

## 从 Android 小组件或链接进入

Android 小组件、通知或深链接可能带着一个“进入后应该打开什么”的意图。正常情况下，应用会先等工作区和当前用户状态就绪，再执行跳转或回调。

如果从小组件打开后没有直接看到预期页面：

1. 先确认 NanoFlow 已完成启动和登录恢复。
2. 确认小组件本身是否拿到了当前账户的摘要。
3. 手动打开应用主界面，确认项目是否可见。
4. 再检查 Android 小组件、网络和云端函数配置。

不要把一次跳转失败直接当成项目丢失；它更可能是启动时序、会话或小组件刷新状态问题。

## 启动异常时的处理顺序

1. 等待一小段时间，确认不是首次恢复或网络慢。
2. 看当前是否离线，或是否需要重新登录。
3. 刷新一次页面，不要连续多次刷新。
4. 如果项目看起来为空，先确认账号和网络，再看同步状态。
5. 如果本机有重要未同步内容，先导出，绝不要直接清浏览器数据。
6. 仍无法恢复时，按 [生产排障](../04-deploy-operate/04-production-troubleshooting.md) 的顺序检查部署、Supabase 和日志。
