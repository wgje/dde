# Runtime Entry and Activity Audit

This page is the maintenance index for user interaction entries, self-running runtime activities, and the business logic chains behind them. It is intentionally evidence-oriented: every row points to source handles and the verification gate that should prove a future change.

## Audit Scope

The stability goal is to improve boundary handling, exception isolation, state consistency, duplicate-trigger protection, and async race resilience without changing NanoFlow business rules.

Current evidence was established with NanoFlow CodeGraph context for:

- Workspace shell startup, Android widget bootstrap, startup entry intent, handoff effects, and sync pulse lifecycle.
- Realtime transport, polling fallback, subscribe status handling, transport generation, and resume recovery.
- RetryQueue, ActionQueue, project/task sync operations, and background retry continuation.
- Focus and Black Box capture/sync paths.

This is not a claim that every entry is already fixed. It is the working audit map for continuing the broad hardening goal in small verified slices.

## Verification Rules

- Use CodeGraph or NanoFlow overlay first to locate the chain and tests.
- Write a failing test before changing behavior.
- Prefer controller-level tests for runtime activity boundaries because they isolate timers, generations, and async races.
- For sync changes, run the touched spec plus the closest service-level spec.
- For shell/startup changes, run targeted shell specs and `npx tsc --noEmit --pretty false --project tsconfig.app.json`.
- Keep `npm run quality:baseline` and `npm run quality:baseline:ratchet` as broad structural gates.
